# 任务运行监控中心

端口 `8090` 的 Java Web 监控系统，用于展示一项 Codex 工作流的实时执行过程，等待期间与刚完成步骤的原执行者讨论，其余时间与只读任务助手对话。浏览器访问 Java 服务，Java 服务代理端口 `8080` 的 Python 网关；本系统不连接配置中心的 MySQL 数据库。

## 技术栈

- Java 17
- Spring Boot 4.1
- Java `HttpClient`
- 原生 HTML、CSS 和 JavaScript

Java 根包为 `com.codexflow.console`，Web 控制器、异常映射和
工作流网关客户端分别维护。

## 页面能力

- 每个页面只查看 URL 指定的一项任务。
- 展示任务名称、整体状态、当前步骤和完成进度。
- 步骤正式结果保存 Jira 编号后，在顶部任务名称下展示；复用状态轮询自动更新，刷新页面及运行结束后仍保留。仅读取结构化 `jiraContext.issueKey`，没有编号的任务和历史运行隐藏该行，不从结果文字提取编号。
- 展示每一步的名称、角色、状态、起止时间和结果。
- 在对应步骤结果中内嵌预览图片；其他格式显示文件名、大小和下载入口。
- 根据真实生命周期事件显示“任务进度”；正式咨询回复标记为“任务助手”。
- 独立“显示执行详情”开关默认关闭，仅在当前浏览器记住选择，不影响钉钉或运行快照。开启后按步骤标识、折叠展示模型提供的思考摘要、执行说明、讨论过程及工具状态和可用文本结果；不代表完整内部推理。监督机自由播报和内部工具操作始终隐藏。切换保留已加载的正式对话，重新加载最近一页详情；请求失败也不清空已读消息。较早记录通过“加载更早消息”读取；未保存的摘要不能补回；旧版已截断且缺少轮次标识的工具记录可能保留为两条，不推测合并或回写历史。
- 在任务助手区域咨询最新进度，刷新页面后恢复完整对话。
- 非等待期间，助手可查询指定步骤的历史记录，并对已结束步骤发起独立只读核查；执行中的步骤只查已有记录。`chat.assistant.progress` 默认只更新提问处理状态，开启详情时保留过程记录，刷新按事件恢复。咨询不自动返工或放行等待；不能读取原会话时回答会说明证据局限。
- 等待期间由刚完成步骤的原执行者回复，明确修改或采纳才保存完整新版交接总结；聊天不触发流程控制。
- 新半自动 SOP 每一步成功后等待手动确认，最后一步显示“确认结束”，不显示倒计时或保持等待按钮；讨论处理结束后仍须点击确认交接最新总结。历史计时运行保留倒计时及保持等待按钮。
- 回复标记“第 N 步执行者”，明确是否已更新总结；非等待期间为只读任务助手。
- 活动任务每两秒刷新一次；终态任务且没有待处理消息后每 15 秒轻量检查，发现重新运行后恢复正常刷新频率。
- 将内部状态转换为普通用户容易理解的中文。
- 不展示内部事件 JSON、执行机信息或会话编号。

本系统不提供任务编辑、提交、取消、尾部重跑或跳过的直接接口。聊天流程控制已移除，只允许通过按钮暂停或继续当前等待；取消运行仍在配置中心操作。

等待期间的任务消息先保持等待，再恢复刚完成步骤的原执行会话；文字继续无效，只有按钮放行。状态 `discussionBusy` 为真时禁用继续，服务端同时校验。新运行无消息时持续等待人工确认，历史运行按原冻结计时规则，刷新不改变等待。

## 启动依赖

对话中显示从钉钉提交给 Codex 的输入图片，可点击查看原图。新增只读代理 `GET /api/workflows/{workflowId}/input-images/{imageId}`，浏览器仍只访问本 Java 服务；本次不增加网页图片上传入口。输入图片不展示为步骤产出。

启动前需要准备：

1. Java 17 和 Maven 3.9 或更高版本。
2. Python 工作流网关，默认地址为 `http://127.0.0.1:8080`。

监控中心可以在网关暂时离线时启动，但查询任务和连接状态会提示不可用。

## 开发启动

本项目 macOS 使用 `mvnd`，Windows 使用 `mvn`。下方 PowerShell 示例用于 Windows；macOS 启动、测试、打包和格式化均使用 `mvnd`，路径使用 `/`。

从仓库根目录执行：

```powershell
Set-Location .\services\workflow-console

$env:CODEX_GATEWAY_URL = "http://127.0.0.1:8080"
$env:SERVER_ADDRESS = "0.0.0.0"
$env:SERVER_PORT = "8090"

mvn spring-boot:run
```

查看指定任务：

```text
http://127.0.0.1:8090/?workflowId=<workflowId>
```

URL 没有 `workflowId` 时，页面只显示任务编号输入框，不展示全局任务列表。

## 打包运行

```powershell
mvn package

$env:CODEX_GATEWAY_URL = "http://127.0.0.1:8080"
java -jar .\target\workflow-console-0.1.0.jar
```

## 增量刷新

监控页活动状态每 2 秒检查一次，终态每 15 秒轻量检查。工作流不存在（404）等不可自动恢复的查询错误会停止自动查询，切回页面或窗口获得焦点也不会重试；页面清除初次加载占位，显示错误和“重新加载”按钮，不将查询失败显示为任务已停止。网络中断、服务异常、408 和 429 保留自动重试；已加载的步骤和消息保留。查询复用状态和结果版本；总结更新后刷新步骤结果和来源标签。

消息首次只读最近 200 条可见事件，“加载更早消息”按游标回看；每轮增量刷新最多一页，底层审计事件仍保存在中央运行库。长期持续输出时限制自动保留的事件数量，较早消息可再次加载。

内网 HTTP 页面使用 `crypto.getRandomValues` 生成 UUID 的兼容方案；失败重试仍复用原消息编号。监控中心不增加直接运行控制接口，也不连接 MySQL。

## 业务接口

系统提供五个读取接口、一个聊天消息接口和两个半自动流转接口：

```text
GET /api/gateway/ready
GET /api/workflows/{workflowId}
GET /api/workflows/{workflowId}/events?after=0&limit=200
GET /api/workflows/{workflowId}/artifacts/{artifactId}
GET /api/workflows/{workflowId}/input-images/{imageId}
POST /api/workflows/{workflowId}/messages
POST /api/workflows/{workflowId}/advance/{gateId}/confirm
POST /api/workflows/{workflowId}/advance/{gateId}/hold
```

消息请求示例：

```json
{"messageId":"浏览器生成的 UUID","text":"第1步还没结束吗？"}
```

相同 `messageId` 的失败请求复用原 UUID 重试；等待讨论先核对原执行结果，不重复派发不确定的修改。终态只支持只读咨询。

其中事件接口代理 Python 网关的历史事件查询，并支持通过 `after` 增量读取。`limit` 的允许范围为 `1` 到 `1000`；可选 `view=monitor|monitor_details`、`tail=true` 或 `before`，响应包含下一页游标与是否存在更早消息。状态接口可选 `knownRevision`、`knownResults`，语义见 Python 模块 README。

详情接口在服务端只提取公开摘要与已知工具的状态、成功文本结果，不发送原始推理、参数、命令、错误对象或图片传输字段；对文本中的常见凭据、URL、IP 地址及内部编号进行过滤，单条最多 8,000 字符并标注截断。这是已知格式过滤，不是对任意自由文字的全面保密保证。正式回答和必要等待操作沿用现有展示规则。

文件接口只代理 Python 网关已经归属到该工作流的附件，不接受本机文件路径。图片使用 `inline` 预览；其他类型强制 `attachment` 下载，所有响应均带 `X-Content-Type-Options: nosniff`。浏览器不会直接访问 Python 网关或执行机文件系统。

## 安全说明

系统没有登录功能，默认监听 `0.0.0.0` 以支持可信内网访问；应通过主机防火墙限制来源，不得将本系统或 Python 网关直接暴露到公网。如只需本机访问，可设置 `SERVER_ADDRESS=127.0.0.1`。

## 独立文档查看页

新版半自动第一步结果区显示全部交付文档，正式方案标注“主文档”并排在首位，旧半自动运行保留单份入口；新版全自动各步骤显示全部已采集文档；未同步且无正文的条目不提供链接。钉钉结束汇总复用相同查看页，点击进入 `document.html?workflowId=...&documentId=...`，读取最新成功保存的正文，显示所属步骤、版本、更新时间和同步失败状态。保留只读代理 `GET /api/workflows/{workflowId}/documents/{documentId}`；不增加编辑、提交或流程控制接口。Markdown 渲染库本地托管，无 Node 构建，禁用原始 HTML、外部图片和危险链接。详见[文档展示说明](../../docs/SOP_DOCUMENT_DISPLAY.zh-CN.md)。


## 业务提前结束展示

状态接口透传可空 `termination`，表示正式步骤报告的阻断或无任务。收尾期间显示“正在结束”，终态区分“因阻断结束”“无待处理任务，已结束”，展示原因及 Jira 备注结果；未启动步骤显示“未执行”。仍使用原有 `failed/completed` 终态停止轮询，页面不新增停止、任务编辑或提交接口。普通讨论不触发停止。详见 [升级与验收](../../docs/SOP_BLOCKED_STOP.zh-CN.md)。

## 半自动最终确认与遇阻等待

新运行透传 `pendingAdvance.kind/nodeId/availableActions` 和可空 `nextNodeId`；等待类型分别为进入下一步、业务遇阻、最终确认。最后一步（包括单步骤）完成后保持运行，必须点击确认才正常结束。新运行不展示截止时间，遇阻一直等待人工处理；历史计时运行仍展示截止时间并按原规则处理。讨论处理和等待动作执行期间禁用确认。

遇阻等待显示原因，提示在钉钉卡片点击“重新执行”，或通过配置中心终止。监控中心不新增取消、重新执行或编辑接口。旧快照沿用原行为；部署与验收见[半自动等待升级说明](../../docs/SOP_SEMI_AUTOMATIC_WAIT.zh-CN.md)。

等待动作处理中（`pendingAdvance.state=busy`）时，当前阶段和步骤等待区统一显示“正在处理步骤操作，请稍候”，不再提示等待人工确认或再次点击重新执行。此状态也用于历史超时收尾，不代表业务步骤已经启动。


## 精简进度展示

消息区展示受理、实际步骤启动和结束等阶段变化，全自动步骤启动合并前一步结果摘要，结束展示业务结论；不重复显示起始步骤首次启动、普通完成或等待播报，重新执行保留启动消息。等待内容与按钮继续在当前等待区展示，正式回答和失败提示保留。结束提示区分流程结束、因阻断结束和无任务，正常与失败终态都保留已确认的业务结论；取消不复用停止前的总结，原始异常不拼入消息。完整结果、文档、耗时仍在步骤详情查看。

监控事件查询使用新的生命周期筛选，刷新、历史回看和游标仍使用原接口；原始审计未删除。需同时更新中央 Python 与监控中心，钉钉详情开关不控制此页面。
