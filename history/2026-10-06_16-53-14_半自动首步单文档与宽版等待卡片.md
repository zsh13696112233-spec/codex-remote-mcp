# 半自动首步单文档与宽版等待卡片

## 本次目的与最终决定

- 优先实现 SOP 文档展示，继续使用普通互动卡片，不切换 AI 卡片或 JSON 构建卡片协议；只考虑桌面宽版。
- 最终限定：仅半自动 SOP 第一个业务步骤且存在下一步时，自动展示一份主文档。主监督不计入步骤；全自动、后续步骤和单步骤 SOP 不采集、不展示文档。
- 不提供步骤开关、多文档列表管理或文档删除功能。文件缺失或同步失败只提示，允许继续；已有正文保留最近成功版本。
- 普通提问不读取或更新文档，第一步等待期间明确修改才同步。改名、更换路径、第一步重试沿用同一运行内的稳定链接；新运行产生新链接。

## 已完成实现

### Python 与文档读取

- 新增 `services/python-workflow/src/workflow_documents.py`：显式单文档清单、路径和文件类型校验、受控远程读取、UTF-8 解码及中央 SQLite 正文快照。
- 仅接受工作目录内 `.md`、`.markdown`、`.txt`，最大 512 KiB；拒绝越界、目录链接、特殊文件、隐藏路径和敏感文件，不扫描目录、不执行替代读取脚本。
- 首步结构化输出为 `summary` 加 `document: {name, path}` 或 `null`，正文不进入主监督公开结果或后续步骤提示词。
- 资格由中央运行模式与步骤身份判断，调用方不能通过旧开关绕过；本机与远程 Sidecar 统一处理，远程仍需机器认证和租约。
- 文档与步骤结果、讨论结果原子保存，批次去重；失败保留旧正文及名称，迟到结果不得覆盖已确认的新总结。
- 保留历史正文及旧链接；若早期第一步已有多份文档，只显示一份主文档，其他旧链接仍可读取。
- 保留正文接口 `GET /workflows/{workflowId}/documents/{documentId}`，不提供文档列表 HTTP 接口。元数据不包含正文或来源路径。

### Java 与桌面阅读页

- 监控中心增加只读正文代理及 `document.html/js/css`，按版本显示最新正文、每 10 秒刷新、失败保留旧内容；继续执行后链接仍可读。
