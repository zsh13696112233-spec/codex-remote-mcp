## 最终实施方案

### 1. 目标与简化原则

Token 直接保存在中央 SQLite 的 Jira 账号记录中，不加密，不增加密钥配置、加解密代码或加密依赖。

保留简单的使用边界：页面保存后不回显 Token，日志、SOP、运行快照和通知不携带 Token，不把 Token 下发到执行机。

配置中心新增“Jira 账号管理”菜单，放在“Jira 领取中心”旁边；SOP 选择本组账号；网关统一采集、预约和核验；监督机继续编排固定工单，执行机沿用本地 CLI 账号处理业务。

### 2. 账号管理与 SOP

- 账号记录包含稳定 ID、所属分组、自定义名称、Jira 地址、Token、执行机账号别名、启用状态、检测结果及实际 Jira 身份。
- 同组名称唯一。自定义名称与执行机账号别名分开，改名称不影响 SOP 引用。
- Java 提供管理页面和代理接口，网关负责存储、检测及使用账号，MySQL 不重复保存 Token。
- 第一版只支持已验证的 Bearer Token。新增账号默认未检测，通过 `/myself` 确认实际身份后才能供 SOP 选择。
- 编辑时 Token 留空表示保持原值。替换 Token 先验证为同一实际账号，成功后更新；失败保留旧值。更换 Jira 服务或实际身份时新建记录。
- SOP 启用 Jira 后，选择当前分组中已启用、检测通过的账号，显示“自定义名称（实际账号）”，保存稳定记录 ID。
- 停用阻止新采集和未创建运行的派发，已有运行继续使用冻结身份。删除采用逻辑删除并清除 Token；有效 SOP、待派发来源或未完成运行仍引用时禁止删除。
- 复用现有跨实例配置写锁，协调 SOP 修改与账号删除，不新增锁框架；分组删除同时检查账号记录。

### 3. 网关采集与固定工单下发

- 网关直接使用 Jira HTTP API v2，设置请求超时、响应大小限制和稳定错误提示，不自动跟随重定向、不输出认证头或原始错误正文。
- 每批确认账号身份，解析唯一名为“开发人”的字段；搜索一次返回工单标题、经办人和开发人，替换逐张开发人补查。
- 保持现有 SOP 项目、状态、`assignee = currentUser()` 和 `Planner` 条件，不扩大领取范围。
- 沿用排除已读取编号的分页方式、1000 项上限，以及完整搜索成功后才发布候选的规则。人员缺失或解析失败显示“未获取”，不单独阻止派发。
- 采集继续由现有定时和手动请求驱动，不新增周期、补采队列或并发调度框架，不占用监督机和执行机。
- 预约核验、启动前复核统一迁到网关，保留原有核验时机、幂等和工单锁。不符合条件时停止本轮，不更换工单。
- 新流程中的 `jira_claim_next` 只获取中央已确认的唯一工单，并准备执行入口，不再自行搜索。
- 执行机继续使用本地账号。准备入口时核对 Jira 服务和实际身份与冻结信息一致，不一致明确失败，不选择其他账号，也不接收中央 Token。
- 跨组仍按“Jira 服务＋工单编号”统一互斥，避免重复处理。

### 4. 接口、快照与历史处理

- 新增 Java `/api/jira-accounts` 及对应网关管理接口，支持列表、新增、编辑、检测、启停和删除。使用版本校验防止并发覆盖及过期检测结果生效。
- SOP 增加 `jira.connectionId`，通过新的 Flyway 迁移增加引用列；旧账号别名字段保留用于历史读取。
- 新运行冻结账号记录 ID、实际 Jira 身份、服务地址、执行机别名及人员展示信息，不包含 Token。
- 账号记录 ID 与 Jira 实际账号 ID 明确区分。改名或同身份替换 Token 不改写已有运行，执行机别名也不反向更新历史快照。
- Java 检查账号分组及可用性；网关在采集、预约和提交边界再次校验。
- 复用已实现的人员存储、冻结快照、领取中心和启动通知展示。监控中心不增加账号管理能力。
- 旧 SOP 逐个绑定新账号，不自动匹配。用户明确表示不处理历史数据：历史仅保留查看，不做账号关联迁移；缺少中央账号的旧快照不直接重试，提示使用已绑定账号的最新配置。不删除或清空历史数据库。
- 页面处理加载、空列表、检测失败、网关离线、失效选项、重复提交和刷新恢复；Token 不写入浏览器持久存储。

### 5. 实施、验证与发布

实施顺序：账号存储与 HTTP 客户端 → 中央采集及运行准备 → Java 接口和 SOP → 管理页面 → 回归验证。

重点验证：

- 分组隔离、名称唯一、Token 替换、实际身份变化、停用、引用删除保护和并发修改。
- 多页、零结果、分页失败、人员空值和多人、重复预约、跨组争抢、启动前资格变化及执行机身份不符。
- 监督机全部忙碌时仍能采集；启动始终处理锁定工单；运行快照、日志和通知不含 Token。
- 现有人员展示、通知去重、分页及刷新行为保持有效。

在已有运行结束后同步升级中央网关、本机 MCP／远程 Sidecar 和配置中心。旧待派发来源停止派发并保留记录；创建、检测账号并逐个绑定 SOP 后恢复调度。

更新 README、部署说明和工作规则：允许中央 Jira 账号记录保存 Token 明文，其他服务配置及机器凭据规则不因此扩大。保留当前已有改动，完成相关测试、差异 review 和最终检查；不自动写 history、提交或推送。
