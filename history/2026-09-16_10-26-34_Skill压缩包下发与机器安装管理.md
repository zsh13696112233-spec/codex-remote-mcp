## 目标与完成范围

配置中心上传单个 Skill ZIP，选择一台或多台执行机下发，检查文件完整性与 Skill 识别状态，复制 `$skill-name` 到 SOP 步骤“执行要求”。支持提示词、Python 等脚本和资源文件。

- 仅首次安装；同名不同内容、无法确认平台归属的人工目录拒绝覆盖。不提供升级、卸载或回滚。
- Python 和第三方依赖由执行机准备；下发过程不执行包内安装程序或业务脚本。
- 复用现有执行服务认证连接，新建独立管理连接传输文件；纯执行机不增加 Sidecar，不通过业务模型会话安装。
- 浏览器只访问 8091；Java 通过 HTTP 访问中央 Python 网关 8080。8090 监控中心未增加管理能力。
- 包文件保存在中央专用目录，安装状态以中央 SQLite 为唯一事实来源；Java 不新增 MySQL 副本。
- 不改变原 SOP Skill/MCP 标签语义，不新增专用 SOP 选择控件。

## 实际实现与主要文件

### Python 包校验、持久化和传输

- `services/python-workflow/src/skill_packages.py`：安全 ZIP/YAML 解析、路径校验、规范化文件清单和内容哈希。
  - 允许根 `SKILL.md` 或一层外包装目录，一个 ZIP 只能包含一个 Skill。
  - 限制 ZIP 20 MiB、解压总量 50 MiB、单文件 10 MiB、最多 500 文件。
  - 拒绝路径穿越、链接、加密、重复路径、大小写冲突及 Windows 非法文件名；忽略明确的 macOS 打包元数据。
  - 使用安全 YAML 加载器，拒绝别名、重复键和对象构造；不执行上传内容。
- `skill_store.py`：新增包、批次、逐机任务、安装归属和幂等动作表；持久化逐文件进度、尝试次数、错误及状态。
- `skill_deployment.py`：Base64 文件传输、回读哈希校验、目录边界和链接检查、归属标记；先资源/脚本后根 `SKILL.md`，最后刷新 Skill 列表并检查名称、路径、启用和解析结果。
- 同一机器串行，最多三台机器并行；初次尝试后最多三次自动重连。网关重启后依持久记录回读核对，不能确认归属时停止，不盲目删除或覆盖。
- 运行库旁 OS 锁防止多个管理进程同时恢复任务；取消后台任务时等待已开始的持久化操作完成，再释放锁。
- `skill_routes.py`：上传、包查询、下发、批次查询、任务重试/检测、机器目录检测和机器安装汇总接口。
- `workflow_gateway.py`：注册接口及管理器生命周期；`workflow_service_config.py` 增加部署配置校验。
- `pyproject.toml`、`uv.lock` 新增 PyYAML 依赖；`.gitignore` 排除包存储目录及运行锁。

### 逐机安装目录改为网页配置

最初设计逐机授权来自中央 JSON；用户要求在机器登记页面配置一次并持续生效，已实现：

- `agent_registry.py` 新增中央 SQLite 表 `agent_skill_settings`，与机器既有编号关联。
- 机器管理编辑页新增 Skill 安装授权开关和目标绝对目录；保存即时生效，刷新及服务重启后保留。
- 原 `skill_deployment.agents` 仅首次为已有机器建立记录时导入；后续以数据库记录为准，旧配置不会重新打开网页已关闭的授权。新登记机器默认未授权。
- 不提高现有 `allow_write` 权限；机器仍需启用、具备执行能力且连接检测通过。
- 检测按钮只检查已保存目录的祖先、类型、读取及 Skill 刷新接口，结果和时间持久化。不写探针文件，不能据此宣称写权限或 Skill 搜索目录已完全验证；实际安装时再验证。
- 有排队/运行中的 Skill 任务时拒绝修改安装设置或连接地址。更改地址使连接检测失效，更改目录清除旧目录检测结果；旧安装文件不自动迁移。关闭授权不删除现有文件。
- 对应网页文件：`static/machines.js`、`machines.css`；机器 API 增加 `skillInstallation` 设置，省略字段时保留旧值。

### 配置中心页面与 Java 代理

- 新增 Java `application/SkillService.java`、`web/SkillController.java`，扩展 `client/GatewayClient.java`。
- Java 限制 ZIP/JSON 请求大小，保留网关业务状态码，对连接/响应错误返回稳定信息。

## 部署与配置要点

- 详细事实以 [Skill 下发部署说明](../docs/SKILL_DEPLOYMENT.zh-CN.md)、[Python README](../services/python-workflow/README.md)、[配置中心 README](../services/role-task-config-center/README.md) 为准，示例维护在 `config/workflow-service.example.json`。
- 中央配置的 `skill_deployment` 必须与 `machine_defaults` 同级；`package_root` 是中央保存上传包的目录。逐机安装根目录则填写在机器管理网页，属于执行机文件系统。
- **自动默认到数据库旁 `skill-packages` 目录仅讨论过，尚未实现。** 当前未配置 `package_root` 仍关闭上传/下发，即使某台执行机授权及目录检测通过也是如此。
- 初次部署本功能需更新 Python 依赖/代码/配置并重启 8080，再更新配置中心 8091。后续网页保存逐机授权无需重启。最后一次紧凑布局调整仅涉及前端，更新 8091 静态资源即可。
- 8090、主监督 Sidecar 无需因本功能重启；执行机支持当前文件/Skill 接口时通常无需重启，升级执行服务本身则按部署方式操作。
- 重启中央网关应避开运行中的工作流，原有中断运行处理语义没有改变。

### 复现命令

Windows，从仓库根目录：

```powershell
$env:PYTHONPATH="$PWD/services/python-workflow/src;$PWD/services/python-workflow"
.venv/Scripts/python.exe -m unittest tests.test_skills tests.test_agent_registry tests.test_workflow_service_config -q
.venv/Scripts/python.exe -m unittest discover -s services/python-workflow/tests -t services/python-workflow -q
```

配置中心模块目录下：

```powershell
mvn fmt:format -Dtest=SkillControllerTest,MachineServiceTest test
node --test src/test/js/skills.test.cjs src/test/js/machine-skills.test.cjs src/test/js/shared-groups.test.cjs
node --check src/main/resources/static/skills.js
```

- Windows 沙箱不能启动 AppData 中基础 Python 时，按 AGENTS 规则在沙箱外运行同一 `.venv` 命令；没有重建环境。会话中为新依赖在现有环境安装了 PyYAML。
- Maven 使用机器已有的 Maven/JDK；macOS 按根 README 改用 `.venv/bin/python`、`PYTHONPATH=...` 和 `mvnd`。不要复制 Windows 环境目录到 macOS。
- 真实本地协议测试需显式设置 `SKILL_TEST_CODEX` 后执行 `tests.test_skill_app_server`，默认跳过。
