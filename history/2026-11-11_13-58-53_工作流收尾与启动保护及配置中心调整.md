## 主要代码与行为变化

### 1. Jira 业务收尾由 SOP 步骤职责决定

- 涉及 `services/python-workflow/src/workflow_outcomes.py`、`workflow_wait_service.py`、`workflow_discussion.py`。
- 平台结果协议不再统一指定停止评论、负责人接收人、Manager 兜底、评论与转交顺序，也不再统一要求 Jira 状态和处理角色保持不变。业务动作及其顺序改由当前步骤职责决定。
- 平台仍要求写入前核对唯一工单及当前状态、写入后回查、结果不明先查询、避免重复写入与并发覆盖，并保留权限和敏感信息保护。
- `jiraComment` 如实报告停止评论结果，字段存在本身不授权新增评论；开发人结果仍读取实际开发人，不以转交对象代替。
- 正式阻断仍结束本轮，不因补齐条件自动恢复，不执行下一步骤。稳定的 `SOP-STOP-` 标记仍提供给职责要求的停止评论使用，标记不构成新增评论授权。
- 半自动等待及等待讨论不属于正式结束，禁止执行停止评论和负责人转交等正式阻断收尾；后续仍由有效等待按钮控制。历史超时入口只依据当前步骤职责处理收尾。
- 总结正文仍沿用 SOP 业务结论格式；平台不再把同一总结格式强加给 Jira 评论。
- 对应测试更新：`test_workflow_outcome_instructions.py`、`test_workflow_outcomes.py`、`test_workflow_waits.py`；覆盖结果版本 1–5、全自动和半自动分支、评论回执、等待与超时提示词。
- 详细行为与迁移说明维护在 `services/python-workflow/README.md` 的“业务阻断与无任务提前结束”章节。

### 2. 网关重复启动在初始化前失败

- 涉及 `services/python-workflow/src/workflow_gateway.py` 和 `skill_deployment.py`。
- 命令行启动先绑定并保留监听 socket，再通过 Uvicorn factory 创建应用，避免端口冲突时先初始化运行库或后台任务。
- ASGI 导入入口继续保留；端口占用和无法绑定地址提供中文错误，启动失败返回非零退出码，退出时关闭监听 socket。
- Windows 使用独占地址选项；其他平台保留地址复用选项。不同网关仍不能绕过中央运行库的下发进程锁。
- Skill 下发进程锁错误提示明确要求正常停止旧进程，禁止通过删除锁文件或运行库绕过。
- 新增 `services/python-workflow/tests/test_gateway_startup.py`，验证重复启动不创建指定数据库目录、不影响原监听、端口预留先于 factory、真实 Uvicorn 生命周期、失败退出与 socket 释放。
- `test_skills.py` 更新锁冲突提示断言。启动及锁保护操作说明同步写入 Python README。

### 3. 定时任务支持一分钟间隔

### 4. SOP 编辑器新增步骤默认值调整

### 5. Jira 请求表字符集迁移

- 新增 `services/role-task-config-center/src/main/resources/db/migration/V51__jira_requests_utf8mb4.sql`。
- 对 `codex_jira_requests`、`codex_jira_dingtalk_requests` 执行 `CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`。
- 目标是修复 V47 在默认 latin1 数据库中建表后，中文任务快照、失败原因和钉钉消息无法保存的问题；不修改已应用的 V47、不调整数据库全局字符集、不删除业务记录。
- 新增 `JiraRequestCharsetMigrationTest.java`：在 H2 MySQL 模式先迁移到 V50，插入旧记录，再应用 V51，验证旧记录保留、中文及表情写入、主键重复拒绝、Flyway 校验及重复 migrate 无新增迁移。
- H2 通过不等于真实 MySQL 字符集转换已验收。部署时由 Flyway 应用迁移，已失败启动不会自动重发，应先核实是否已有受理请求再手动运行。
