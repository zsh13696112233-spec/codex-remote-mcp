## 钉钉 JSON 卡片评估

用户明确偏好代码构建 JSON 卡片，认为外部模板方式维护臃肿。

参考入口：[JSON 构建卡片](https://open.dingtalk.com/document/development/json-build-card)。本次网页读取和浏览器连接均失败，未在线核实该页完整内容；用户随后粘贴了“消息结构与生命周期”协议文本，以下结论以该文本为依据。另查到[钉钉官方卡片示例](https://github.com/open-dingtalk/dingtalk-card-examples)，只能支撑既有模板、创建、更新及回调能力，不能替代新版接入文档。

用户提供的协议说明：

- 四种消息为 `createSurface`、`updateComponents`、`updateDataModel`、`deleteSurface`，每条只包含一种载荷。
- 消息包络 `version` 为 `v1.0`，投递 `protocolVersion` 为 `1.0`，产品能力集 `aicardVersion` 为 `V0.8`；三者含义不同。
- 新卡显式创建画布并填写钉钉 `catalogId`；宿主已创建时不要再次创建。同卡所有消息使用同一 `surfaceId`。
- 组件树根 ID 为 `root`，组件 ID 和引用必须有效、稳定，动态绑定使用前初始化正确类型的数据。
- 仅字段契约支持时可用动态绑定；数据变化更新数据模型，结构或普通字段变化更新组件。
- 钉钉协议是 A2UI 的子集加扩展，不可直接替换成通用 A2UI 实现。
- `catalogId` 是运行时标识，不是下载地址；钉钉当前不执行以 `null` 删除数据字段的语义。

建议由配置中心 Java 固定构建组件 JSON，执行步骤只提供总结和文档数据，不让业务执行者自由生成按钮和整张卡片。

卡片建议分总结、文档、操作区域；无文档不生成文档区域。保留现有等待、讨论处理中禁用、过期按钮拒绝及按钮放行规则。持久化卡片与画布对应关系，避免发送重试重复创建，控制更新顺序，防止旧内容覆盖新版本。具体折叠、页签、Markdown 文档组件尚未核实，不作为已支持功能。

## 旧版清理的讨论结论

新版完整可用后可以删除旧实现，不必长期维护两套：

1. 切换期新卡使用新协议，保留旧卡更新和回调，等待旧卡关联的活动流程结束。
2. 验证新版发送、更新、引用回复、按钮及失败重试，并确认没有活动流程依赖旧卡后，删除旧模板构建、发送、更新、专用配置和相应测试文档。
3. 历史记录不删除，已应用 Flyway 迁移不修改；废弃字段如需删除，通过新迁移处理。
4. 可保留很小的过期回调处理提示旧卡失效，防止旧按钮误操作当前流程，无需因此保留整套旧版。
