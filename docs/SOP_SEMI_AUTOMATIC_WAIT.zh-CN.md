# 半自动三类等待升级与验收

新半自动文字交接运行在中间成功、业务遇阻和最后成功时都等待人工处理。正常确认默认 2 分钟，遇阻默认 30 分钟，在 SOP 内分别配置；最后一步共用正常确认时长。具体接口与状态以三个模块 README 为准。

## 上线顺序

1. 停止提交新任务，等活动任务结束，按现有流程备份数据库。本次不支持恢复重启前的运行。
2. 更新中央 Python 网关及实际使用的本机 MCP 或远程 Sidecar；网关和本机 MCP 继续使用同一运行库。所有执行端同步更新后再启动新策略运行。
3. 导入并发布 `config/sop等待卡片_桌面宽版_单文档.json`。可更新现用宽版模板；若发布成新模板，配置 `DINGTALK_DOCUMENT_CARD_TEMPLATE_ID` 为新 ID。不得留空回退旧单按钮模板。当前默认模板 ID 为用户提供的 `35c2fa5f-c25c-4d4b-8abd-dd07c953b14d.schema`；如环境变量仍指定旧 ID，需同步更新。模板 ID 已接入，真实投递和按钮操作仍待验收。
4. 构建并重启配置中心 8091、监控中心 8090。配置中心自动应用 V39，新增时长默认值，不修改旧提交快照。Windows 使用 `mvn`，macOS 使用 `mvnd`。
5. 将线上三个角色职责同步为仓库 `sop/plan.txt`、`sop/code.txt`、`sop/review.txt` 的新规则。系统不会自动覆盖数据库内角色配置。
6. 检查 SOP 两项时长，按最新配置启动新运行。旧快照重试仍走旧规则，不会因升级自动增加最后确认或遇阻等待。

## 卡片与用户操作

| 场景 | 主按钮 | 无回复到期 |
| --- | --- | --- |
| 中间步骤成功 | 进入下一步 | 自动进入下一步 |
| 业务遇阻 | 重新执行 | 正式阻断收尾并结束 |
| 最后步骤成功 | 确认结束 | 正常结束 |

每张新等待卡片还有“终止任务”，表示人工取消，保留已有结果，不回滚文件、提交或 Jira 操作，不发送阻断开发人通知。只有当前有效卡片能操作当前等待。

截止时间从服务端进入等待起算，不因卡片延迟发送而延长；发送失败不表示用户已看到。人工消息送达后取消本轮倒计时，讨论结束由按钮处理。重复消息不会影响后续步骤；机器人回复不会重新计时。遇阻讨论不等于已经完成当前步骤，“重新执行”后只处理当前步骤，成功或再次遇阻都会生成新一轮等待。

新版模板增加 `confirmLabel`、`confirmAction`、`showStop`、`stopStatus`；主按钮动作是 `advance_confirm` 或 `advance_retry`，终止动作是 `advance_stop`。两者均传回 `workflowId/gateId`，使用后端返回的 `confirmRequestSucceeded` 判断本次回调是否成功，不在客户端自行宣告流程成功。

## 验收

- 使用短等待时长验证中间自动继续、遇阻超时阻断、最后一步自动正常结束，以及单步骤最终确认。
- 在截止前回复文字或图片，确认计时取消、原执行者回复、普通提问不修改结果；明确修改后最终确认使用最新结果。
- 遇阻首次不写停止评论、不转交 Jira；补充信息后重新执行只处理当前步骤。再次遇阻重新计时；超时才执行 Jira 收尾及现有开发人通知。
- 分别点击三个主按钮及终止，验证重复点击、旧卡片、讨论忙碌、刷新、取消与到期竞争。未知写入不得重复执行或放行。
- 验证两项时长保存、旧值省略保留、修改配置不影响原快照；全自动及旧快照维持原行为。
- 本机和远程各验收一次；正式 MySQL 8 迁移、真实钉钉双按钮显示及 Jira 操作必须在实际环境单独验收。

等待仍占用运行名额。网关重启或远程租约失效仍按原规则中断；本次不新增恢复、任务迁移、通用定时管理或任意步骤重跑。
