# 钉钉统一入口与图片对话升级

先升级中央 Python 网关及本机 MCP，再升级远程 Sidecar，最后升级配置中心和监控中心。按既有流程备份 MySQL 和 SQLite；不清库、不修改历史迁移。配置中心新增 Flyway V20，移除通知对象的一对一限制，并为对话记录增加来源会话、图片引用和确认操作信息。

## 行为变化

- 启动命令为 `@机器人 完整任务定义名称`，不再使用空 @ 或“运行”定位固定群任务。名称应避免重复。启动不带图片。
- 所有能接触机器人的用户均可启动、查询和提出控制要求，任务或通知对象的启用设置不再充当人员权限。
- 后续使用完整工作流 ID 加问题；引用关联任务消息可省略 ID。无法解析引用时，改用编号，不依赖最近会话上下文。
- 对话在提问会话回复并 @ 提问人。引用优先使用实际消息标识；部分钉钉回复不返回消息标识时，只在当前会话最近 50 条已发消息中精确匹配引用正文，匹配不唯一或客户端不提供正文时要求带编号。
- 钉钉启动只回复启动结果和查看入口，不推送后续进度、完成或等待提醒。网页与定时运行继续按主动通知开关和配置对象推送；通知对象可被多个任务复用。
- 控制确认关联具体操作及提议人，网页不能代替钉钉提议人确认其操作；网页可正常提出并确认自己的操作。

## 图片部署要求

机器人需要调用钉钉机器人文件下载接口的权限。只支持实际发送给机器人的图片或富文本图片，不监听普通群消息中的全部图片。请把工作流编号、文字需求和图片一起发送，或引用关联图片消息补充需求。

每条消息最多 5 张 PNG、JPEG、WebP，合计最多 20 MB；输入图片与当前及历史产出共同遵守每个工作流 50 个文件的上限。输入原图保存在中央 SQLite 的独立表，不混入步骤产出。确认返工后原图关联目标步骤和后续步骤，原始运行快照不变。

需要收图的任务助手和步骤执行机必须配置绝对 `artifact_root`，并允许 `allow_write`。这是托管输入文件的写入许可，不改变 Codex 任务本身的只读/写入权限。只读任务仍按原沙箱执行。原图由 Python 经现有 app-server 连接写入目标执行机的 `artifact_root/conversation-inputs/<jobId>/`，随后通过 `turn/start` 的 `localImage` 输入交给 Codex。

目标 app-server 必须支持 `fs/createDirectory`、`fs/writeFile` 和图片输入。缺少能力、没有托管目录或传图失败时请求失败，不把中央机器路径当成远程路径，也不静默退化为纯文字。远程 Sidecar 使用已有机器身份与当前租约从中央读取所属工作流的步骤输入图；不需要开放新的公网端口。这不启用远程 `cumulative_files` 通用产出交接。

## 验证

使用测试群分别验证名称启动、多人重复启动、跨群带编号提问、回复自动 @、引用消息与编号冲突、图文问答及确认后的按图返工。网页与定时运行各验证一次主动通知，钉钉启动验证无后续主动通知。

文件下载失败、会话回复地址失效或 app-server 文件接口不可用时由用户重新发送。本次不新增重启恢复、断线补发或图片自动重传。现有任务运行及主动通知恢复逻辑沿用。输入文件保留供同一对话与已确认返工使用，不增加清理后台任务。
