# 角色任务配置中心与 Codex 运行监控中心需求规格说明书

> 本文档是后续新会话实施本项目的唯一需求依据。除非需求方另行确认，实施范围、系统边界、接口、数据结构及验收标准均以本文档为准。

## 一、系统架构

建设两个相互独立的 Java Web 系统。两个系统均使用 Java 17 和 Spring Boot 4.1。

### 1. 角色任务配置中心

- 建议服务端口为 `8091`。
- 将现有 `role-management.html` 迁移为正式的 Spring Boot Web 系统。
- 负责角色、SOP、任务定义和运行参数配置。
- 使用 MySQL 8 持久化数据，使用 Flyway 管理数据库结构变更。
- 由服务端直接调用 Python 网关 `8080`，浏览器前端不直接调用 Python 网关。
- 负责提交、取消和重新执行任务。
- 任务提交成功后，携带返回的 `workflowId` 打开 `8090` 监控页面。

### 2. 任务运行监控中心

- 使用现有 `workflow-console`，服务端口保持 `8090`。
- 删除任务定义、节点编辑、任务提交、任务取消和任务重试功能。
- 每个页面只展示 URL 指定的一项任务。
- 访问格式：

```text
http://<host>:8090/?workflowId=<workflowId>
```

- 从 Python 网关 `8080` 读取任务进度、步骤结果、重跑额度和任务助手消息。
- 不连接角色任务配置中心使用的 MySQL 数据库。

### 3. 系统调用链路

```text
8091配置任务
  → 8091服务端提交到8080
  → 8080启动Codex工作流
  → 打开8090/?workflowId=xxx
  → 8090从8080读取并展示运行过程
```

## 二、配置中心功能

### 1. 角色管理

角色包含以下字段：

- 角色 ID。
- 名称。
- 职责。
- 启用状态。
- 创建时间和更新时间。
- 数据版本。

角色管理支持以下操作：

- 新建。
- 编辑。
- 搜索。
- 启用。
- 停用。
- 删除。

业务规则：

- 已被未删除 SOP 引用的角色不能直接删除，只能停用；仅被已删除 SOP 的历史步骤引用时执行软删除并从角色列表隐藏。
- 不迁移原 `localStorage` 数据。
- 系统首次启动时初始化当前三个默认角色。

### 2. 运行状态

配置中心左侧提供独立“运行状态”菜单，不依赖新建或打开 SOP。页面只通过配置中心服务端代理读取 Python 网关，不允许浏览器直连 `8080`。

页面展示：

- Python 网关是否可用。
- 全部已登记主监督执行机，以及在线空闲、在线忙碌、离线、未知或停用的数量汇总。
- 单台主监督的执行机 ID、默认模型、并发容量、最近探测时间和最近在线时间。
- 绿色表示在线空闲，蓝色表示在线忙碌，红色表示离线，灰色表示状态未知或停用。

页面可手动刷新，并在可见时每 `10` 秒自动刷新。离线判定由 Python 网关完成：连续两次轻量连接探测失败才标记离线；如果 Python 网关本身不可用，主监督统一显示状态未知，不推断为离线。页面不得展示执行机地址、令牌、工作目录或底层异常。

### 3. SOP 管理

SOP 是可重复使用的串行工作流模板。

SOP 包含以下基础字段：

- SOP ID。
- 名称。
- 说明。
- 主监督执行机。
- 失败策略，默认某一步失败后停止。
- 主监督最长运行时间，默认 `7200` 秒。
- 单次工作流人工重跑总额度，默认 `10` 次，范围 `0–100`。
- 流转方式：`automatic` 全自动（默认）或 `semi_automatic` 半自动。
- 结果交接方式：`cumulative_files` 文件交接（默认）或 `legacy_text` 文字交接。
- 步骤默认模型。
- 启用状态。
- 创建时间和更新时间。

删除 SOP 时，如果仍有未删除的任务定义引用则拒绝并提示停用；否则执行软删除并从配置列表隐藏，以保留已软删除任务和历史运行所需的外键关系。

### 4. SOP 模型配置

在 SOP 编辑页面增加“步骤默认模型”下拉框。

默认值必须为：

```text
gpt-5.6-sol
```

第一版下拉选项为：

```text
gpt-5.6-sol
gpt-5.6-terra
gpt-5.6-luna
```

模型作用范围和继承规则：

- SOP 的步骤默认模型只作用于 SOP 的执行步骤。
- SOP 的步骤默认模型不作用于主监督会话。
- 主监督会话继续使用其执行机的默认模型。
- 每个步骤默认继承 SOP 的步骤默认模型。
- 单个步骤允许单独覆盖模型。
- 步骤未覆盖模型时，提交 JSON 中使用 SOP 的默认模型 `gpt-5.6-sol`。
- 配置页面显示模型的中文说明，提交时使用完整模型 ID。

### 5. SOP 步骤

每个 SOP 步骤包含以下字段：

- 步骤 ID。
- 顺序号。
- 显示名称。
- 引用的角色。
- 本步骤执行说明。
- 期望输出。
- 执行位置：本机或远程。
- 执行机 ID。
- 工作目录。
- 是否允许写入，默认关闭。
- 使用模型，默认继承 SOP 的 `gpt-5.6-sol`。
- 最长运行时间，默认 `1800` 秒。
- Skill 标签。
- MCP 标签。

第一版只支持严格串行执行：

```text
第1步：无依赖
第2步：依赖第1步
第3步：依赖第2步
```

Skill 和 MCP 在第一版只保存和展示，具体限制如下：

- 不影响真实执行权限。
- 不写入步骤提示词。
- 不自动安装或启用。
- 页面明确显示“当前仅作为配置标签”。

执行机列表由配置中心调用 Python 网关 `GET /agents` 获取。响应中的 `permissionProfiles` 决定节点可选权限档位；旧网关缺少该字段时按 `allowWrite` 降级为原有只读/写入能力。

### 6. 任务定义

任务定义包含以下字段：

- 任务定义 ID。
- 任务名称。
- 任务目标和背景。
- 选择的 SOP。
- 补充说明。
- 启用状态。
- 创建时间和更新时间。

任务定义支持以下操作：

- 新建。
- 编辑。
- 复制。
- 删除。
- 搜索。
- 保存后重复执行。
- 查看运行记录。
- 取消运行中的任务。
- 按原运行快照重试。
- 使用最新任务配置再次运行。

每次运行必须保存一份不可修改的快照，内容包括：

- 任务内容。
- 角色职责。
- SOP 配置。
- 步骤配置。
- 各步骤最终使用的模型。
- 提交到 `8080` 的完整 JSON。
- `workflowId`。
- 提交时间和返回结果。

### 7. 钉钉通知对象

- 一个钉钉机器人可以处理多个任务定义。每个任务定义最多绑定一个通知对象，对象类型只能是人员或群聊；同一对象只能绑定一个任务定义，多个任务定义可以复用同一个 SOP。
- 公司人员由 8091 管理员手动从钉钉通讯录同步，首次同步默认停用；人员离开可见通讯录后标记为不可用并自动停用，不做定时同步。
- 群聊在群内首次 @ 机器人后自动登记，默认停用；管理员确认名称、测试并启用后才可供 SOP 选择。
- 从钉钉启动任务前，必须按消息来源解析任务绑定，并校验任务及目标已启用、仍可用且属于当前 Client ID。机器人可以在没有任务绑定时连接，以便发现群聊。
- 同一任务绑定同时最多运行一个工作流，不同绑定可以并发；所有对话和控制必须按目标与工作流绑定隔离。
- 只有从配置目标发起的钉钉运行建立消息绑定并回推钉钉；8091 页面发起的运行不回推。群目标允许群内成员 @、回复或引用消息进行咨询和控制；人员目标仅允许该人员在单聊中直接咨询和控制。
- 个人消息只发送文本或 Markdown；群聊可以使用可选互动卡片。运行绑定和 Outbox 必须冻结目标类型与外部 ID，配置变更不得改变历史运行去向。

## 三、工作流生成规则

### 1. 步骤基础提示词

每个步骤使用以下基础提示词模板：

```text
任务名称：
{任务名称}

任务目标：
{任务目标和业务背景}

你当前负责：
第N步：{步骤名称}

你的角色：
{角色名称}

你的职责：
{角色职责}

本步骤执行要求：
{步骤执行说明}

期望输出：
{期望输出说明}

请只完成当前步骤，不要代替其他步骤执行。
请使用普通用户容易理解的语言返回结果。
```

### 2. 工作流 JSON 生成规则

- 每次运行生成一个新的 UUID，作为 `workflowId`。
- 使用最新配置创建的运行把 SOP 选择的结果交接方式写入 `handoffMode`；按历史快照重试保留原提交 JSON，不为旧快照补写字段。
- `name` 使用任务名称。
- `supervisorAgentId` 来自 SOP 的主监督执行机。
- 不设置 `supervisorModel`，让主监督会话使用其执行机的默认模型。
- 每个 SOP 步骤转换为一个 node。
- node 的 `model` 优先使用步骤覆盖模型；步骤没有覆盖时，使用 SOP 默认模型 `gpt-5.6-sol`。
- 第一步没有依赖，后续每一步只依赖它的前一步。
- 执行位置、执行机、工作目录、权限档位和超时时间来自 SOP 步骤配置。权限档位固定为 `read_only`、`workspace_write`、`auto_review`，新步骤默认只读，不提供完全访问和人工审批。

## 四、步骤产物交接

SOP 可选择 `cumulative_files` 或 `legacy_text`。默认的 `cumulative_files` 不得把任何前序文字结果或前序步骤返工要求传入下一步；第 N 步自动获得第 1 至 N-1 步当前有效的全部文件，并获得来源步骤、文件名、大小、MIME 和执行机绝对路径清单。未发布文件的历史步骤显式标为“无文件”。`legacy_text` 只把直接上一步的文字结果追加给下一步，适合不发布文件的纯文本串行任务。

旧快照字段缺失时按 `legacy_text` 兼容，只在此模式下向后一步追加直接依赖的文字结果：

```text
前一步已经完成，下面是它提供的结果：

【第1步结果】
{前一步结果}

请基于以上结果完成你当前负责的步骤。
```

文件模式执行和容量限制：

- 只有前一步成功后，才能启动下一步。
- 每次尝试使用本机 `artifact_root` 下的独立 `inputs/step-N/` 与空 `output/`，只向 Agent 传递绝对路径，不使用 Base64，也不扫描业务工作区；远程固定目录上传不在本版本范围内。
- 所有步骤都允许零个或一个文件；`write` 只控制写权限，不代表必须生成文件。步骤是否完成只取决于节点执行结果，没有文件时由需要该文件的后续步骤自行判断并按业务规则处理。
- 单文件最多 `20 MB`，单工作流当前与历史文件合计最多 `50` 个，按 SHA-256 去重。
- 最终提示词最多 `100,000` 个字符。
- 同时保存原始提示词和实际执行提示词。
- 前一步失败时，按照 SOP 失败策略处理，不生成虚假结果。
- 前序文件只是可用输入；当前步骤没有明确要求使用时，不得打开、引用或合并。

## 五、8090 任务运行监控中心

### 1. 删除的功能

8090 必须删除以下功能：

- 工作流编辑器。
- 添加节点和删除节点。
- 提交按钮。
- 取消按钮。
- 重试按钮。
- A、B、C 示例模板。

### 2. 展示的内容

8090 必须展示以下内容：

- 任务名称。
- 整体状态。
- 当前执行到第几步。
- 已完成步骤数和总步骤数。
- 串行步骤进度。
- 每一步的角色、状态、时间和结果。
- 每一步发布的图片在对应结果内预览；其他格式显示文件名、大小和下载按钮。
- 主会话完整消息时间线。
- 最终任务总结。
- 网关连接状态。
- 半自动等待中的前后步骤、剩余秒数，以及“立即进入下一步”和“暂停，暂不进入下一步”按钮；暂停后显示“继续进入下一步”。页面必须说明暂停不会自动返工，结果不符合要求时应在任务助手中描述修改点。任务助手提出返工时，应在二次确认前展示 AI 总结的返工要求；确认后该要求追加到目标步骤实际提示词末尾，且不得修改原始运行快照。

页面每 `2` 秒刷新一次；任务进入结束状态后停止刷新。

### 3. 状态中文转换

页面必须将内部状态转换为普通用户容易理解的中文：

```text
queued       → 等待开始
running      → 正在进行
completed    → 已完成
failed       → 未完成
cancelled    → 已停止
interrupted  → 已中断
```

### 4. 页面隐藏信息

普通页面不得展示以下内容：

- MCP。
- `thread`、`turn`、`job`。
- `agent`、`executor`。
- 原始事件 JSON。
- 英文状态码。
- 内部审批和调用过程。

当 URL 没有 `workflowId` 时，页面只显示任务编号输入框，不显示全局任务列表。

```text
GET    /api/roles
POST   /api/roles

DELETE /api/roles/{id}

GET    /api/sops
GET    /api/sops/{id}
POST   /api/sops

DELETE /api/sops/{id}

GET    /api/task-definitions
GET    /api/task-definitions/{id}
POST   /api/task-definitions
PUT    /api/task-definitions/{id}
DELETE /api/task-definitions/{id}

POST   /api/task-definitions/{id}/runs
GET    /api/task-definitions/{id}/runs
POST   /api/task-runs/{workflowId}/cancel
POST   /api/task-runs/{workflowId}/retry

GET    /api/agents
GET    /api/gateway/ready

GET    /api/dingtalk/targets
POST   /api/dingtalk/targets/sync-people
PUT    /api/dingtalk/targets/{id}

```

### 2. Python 网关新增接口

```text
GET /agents
```

安全要求：该接口不得返回 token、环境变量值或认证信息。

### 3. 8090 监控与半自动流转接口

8090 只保留以下读取、消息和半自动流转接口：

```text
GET /api/gateway/ready
GET /api/workflows/{workflowId}
GET /api/workflows/{workflowId}/events
GET /api/workflows/{workflowId}/artifacts/{artifactId}
POST /api/workflows/{workflowId}/messages
POST /api/workflows/{workflowId}/advance/{gateId}/confirm
POST /api/workflows/{workflowId}/advance/{gateId}/hold
```

文件接口只代理 `8080` 已持久化并归属到当前工作流的附件，不允许浏览器传入任意本机路径。非图片必须强制 `attachment` 下载，所有附件响应都必须带 `X-Content-Type-Options: nosniff`。
流转接口只允许暂停或放行当前工作流返回的 `pendingAdvance`；不提供直接提交、取消、重试或跳过接口。

## 七、数据库与部署

### 1. 配置中心数据库

配置中心使用 MySQL 8 和 Flyway，数据库至少包含以下表：

```text
roles
sops
sop_steps
sop_step_skills
sop_step_mcps
task_definitions
task_runs
dingtalk_targets
```

### 2. 配置中心环境变量

```text
SERVER_PORT=8091
MYSQL_URL
MYSQL_USERNAME
MYSQL_PASSWORD
CODEX_GATEWAY_URL=http://127.0.0.1:8080
WORKFLOW_MONITOR_URL=http://127.0.0.1:8090
DEFAULT_STEP_MODEL=gpt-5.6-sol
```

### 3. 监控中心环境变量

```text
SERVER_PORT=8090
CODEX_GATEWAY_URL=http://127.0.0.1:8080
```

### 4. 部署安全边界

- 第一版不实现登录功能。
- 两个 Java Web 系统和 Python 网关只允许在可信内网访问。
- 所有服务不得直接暴露到公网。

## 八、验收标准

实施完成后必须验证以下内容：

1. 8091 能创建角色。
2. 能创建包含三个串行步骤的 SOP。
3. SOP 默认模型显示为 `gpt-5.6-sol`。
4. 新增步骤自动继承 `gpt-5.6-sol`。
5. 单个步骤可以覆盖为 Terra 或 Luna。
6. 主监督不使用 SOP 步骤模型。
7. 能创建并重复执行任务定义。
8. 8091 能成功提交到 8080。
9. 提交成功后能打开对应的 8090 页面。
10. 8090 不能提交、取消或重试；仅允许暂停半自动 SOP 当前等待，或确认并进入下一步。
11. 后一步能收到前一步结果。
12. 三个步骤严格串行。
13. 主会话消息使用普通用户容易理解的中文。
14. 每次运行生成不同的 `workflowId`。
15. 旧运行快照不受后续配置修改影响。
16. MySQL 和服务重启后配置仍然存在。

## 九、第一版不包含

- 登录和多用户权限。
- 并行步骤。
- 任意依赖图。
- Skill/MCP 的真实权限控制。
- 8090 全局任务列表。
- 8090 取消和重试。
- 旧 `localStorage` 数据迁移。
- 消息队列。
