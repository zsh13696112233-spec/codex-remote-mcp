# 统一分组升级说明

## 升级与兼容

先更新中央 Python 网关，再更新配置中心。配置中心启动时自动执行新增 Flyway V28；不修改旧迁移，不删除数据库，也不重写已保存的运行快照。按现有部署流程备份 MySQL 与中央运行库，保留原数据库路径。

中央 SQLite 中的机器分组继续作为唯一目录，已有分组编号和机器归属保持不变。MySQL 只保存业务数据引用的分组编号、运行冻结的分组名称以及跨实例配置写入锁，不另建分组目录。浏览器仍只访问 8091 的 `/api`；8090 无需升级此项功能。

新配置中心的角色、SOP、任务定义和定时规则保存请求必须提供 `groupId`，旧客户端省略时会收到参数错误。Python 工作流提交的 `groupId` 为可选字段：旧独立工作流仍可不传；传入时必须是有效分组编号，且所有所选机器必须属于该组。网关预检后还会在创建运行的 SQLite 写事务中复核归属，防止机器并发改组。运行中的机器不能改组。

## 处理现有配置

1. 进入“分组管理”，复用已有机器分组，或新建需要的分组。
2. 在“角色管理 → 全部分组”勾选角色，点击“归组 / 改组”。同类数据最多一次选择 200 条，校验失败时整批回滚。
3. 在“SOP 工作流 → 全部分组”归组 SOP。步骤角色须已归入目标组，主监督与步骤执行机也须在该组。原来跨组共用的角色需按现有全局名称规则新建不同名称的角色，再调整 SOP 引用。
4. 在“任务定义 → 全部分组”归组任务，所选 SOP 必须属于目标组。仍有活动运行的任务需等待原运行结束后再归组。
5. 定时规则自动跟随任务归属。任务完成首次归组后，系统从归组时刻重新计算下一次计划时间，并清除旧待触发标记，不补跑归组前错过的时间。

所有旧业务配置和旧运行初始均为“待归组”，不根据当前机器或任务关联推断历史归属。待归组任务不能通过网页、定时或钉钉创建新运行。原有活动运行、提交恢复和后台对账继续使用原编号、原快照，不被归组迁移中断。

旧运行永久留在待归组，可查看、观察和使用既有原运行交互；禁止从这类旧记录新建“按原快照重试”。如需新运行，先完成任务归组，再使用最新配置运行。

## 日常管理

分组管理展示角色、SOP、任务定义、定时规则和机器数量，停用但未删除的数据仍计数，兼任主监督与执行机的机器只计一次。点击数量进入相应分组列表。各业务页面仅提供全部和具体分组筛选，不再展示待归组入口及提示区；旧链接自动返回全部；分组与页面写入 URL，刷新恢复。

角色被有效 SOP 引用、SOP 被有效任务引用、任务存在定时规则或活动运行时，不能直接改组。机器改组同时校验有效 SOP 与活动运行。先解除或调整关联，再改组；系统不会自动搬迁整条业务链。

新运行保存创建时的分组编号与名称。之后的配置改组或分组重命名不改变历史显示；按新运行快照重试继续使用原组，并重新检查机器。分组存在配置、机器或运行历史引用时不能删除，包括软删除记录保留的引用，因此统计为零也不一定可删除。

分组用于业务组织和同组关联校验，不新增用户权限体系。钉钉启动语法与原名称规则保持不变；任务运行目录仍只展示已有约定的钉钉与定时来源。

## 验证

沿用根 README 的 Java/Python 测试命令。前端逻辑回归无需安装依赖：

```powershell
node --test services/role-task-config-center/src/test/js/shared-groups.test.cjs
```

重点验收：旧数据待归组、顺序归组、跨组保存拒绝、批量失败回滚、并发删除保护、旧运行重试拒绝、归组后定时不补跑，以及刷新恢复。前端逻辑测试不等同于浏览器视觉验收；正式升级仍应在 MySQL 8 与实际浏览器中检查布局及端到端运行。
