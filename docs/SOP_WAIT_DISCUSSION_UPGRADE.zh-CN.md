# SOP 等待讨论升级与验收

## 行为变化

等待期间由刚完成步骤的原执行者回答，用户明确提出修改或采纳时保存完整最新版交接总结。点击继续按钮后下一步读取该总结和共享工作目录。全部步骤在同一实际目录由使用者保证，选择文字交接 `legacy_text`，不增加文件传输和目录校验。

所有聊天流程控制移除，包括文字继续、停止、跳过和返工。停止使用配置中心取消入口；步骤执行中的取消限制不变。非等待期间保留只读任务助手。钉钉旧返工和停止按钮失效，不再投递新的控制卡片。

## 部署

1. 结束活动运行，停止三个服务及旧本机编排/远程 Sidecar 进程，避免新旧协议混用。
2. 按既有运维流程备份运行库；不删表、不清库、不删除 Flyway 记录。
3. 同步升级 Python 网关、本机 MCP/远程 Sidecar 和两个 Java 服务。Python 启动时兼容新增讨论记录表和入站接收标记；本次无 MySQL 迁移。
4. 重建两个 Java 模块并重启，刷新网页静态资源。钉钉沿用已有等待模板与继续按钮，`restartMode/stopMode` 固定关闭，`confirmStatus` 在讨论处理中禁用；无需新模板 ID。

原动作、执行历史、额度配置字段和冻结快照保留兼容，不代表仍支持创建返工。历史 `cumulative_files` 运行不自动转换；新共享目录 SOP 应选择文字交接。

## 验收

- 两个串行步骤：第一步生成计划，等待时讨论原因不修改结果；明确说“取消支付，只保留登录”后显示完整新总结，点击继续后检查第二步实际收到的新要求。
- 原会话、实际目录、模型和权限保持一致；原会话不可恢复时明确失败，不新建替代会话。
- 多轮修改、重复消息、断线重试不重复执行修改；回答生成和保存期间按钮禁用，直接请求继续也被拒绝。
- 旧卡片、迟到回复不能修改下一步骤；文字“继续／停止／跳过／返工”不能触发流转。
- 配置中心取消等待中的任务会先核对活动讨论确已停止；不能确认时不宣称成功。文件修改不是事务，失败时可能存在部分文件改动，回答应说明限制，保持等待。
- 无人回复仍两分钟自动继续；讨论后只能按钮继续；网页刷新、钉钉群与个人引用及图片入口保持可用。

无法确认远端启动结果时，不重发、不自动放行；保留诊断记录并核对执行服务后处理。网关重启仍把遗留活动工作流标记失败，不能据此推断远端文件修改一定停止。

自动化验证使用隔离数据库和执行服务替身。真实 MySQL、远程执行机和钉钉模板按钮需要部署后验收。
