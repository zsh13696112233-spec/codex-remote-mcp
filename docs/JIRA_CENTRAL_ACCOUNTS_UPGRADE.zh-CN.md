# 中央 Jira 账号与 HTTP 采集升级

本次将采集、预约核验和启动前复核移到中央网关，账号按分组管理。详细接口和凭据规则见 [Python README](../services/python-workflow/README.md#中央-jira-账号管理)，页面和 SOP 规则见[配置中心 README](../services/role-task-config-center/README.md#jira-统一领取与分组台账)。

## 升级顺序

1. 停止新的任务触发，等待已有运行结束并确认执行已停止。
2. 同步升级中央网关、本机 MCP／远程 Sidecar 和配置中心；远程 Sidecar 不配置或读取 SQLite。SQLite 自动增加账号表，配置中心应用新的 Flyway V48 引用列，保持 `ddl-auto=validate`。
3. 网关启动时停止缺少中央账号的旧待派发来源，保留其记录。历史运行保留查看，不迁移或猜测账号关联，不清库。
4. 在 8091 的“Jira 账号管理”按组新增账号并检测，确认自动映射的“执行机 Jira 账号”为登录账号名；执行机预先配置相同服务、身份和同名的本地 Jira CLI 账号。已有中央账号需重新检测，不能手填执行机别名。Token 只存中央账号表，不放入服务配置、MySQL、运行快照或执行机。
5. 逐个编辑 SOP 选择本组账号，确认项目、状态和 Planner 条件后保存，再恢复触发。缺少中央账号的旧快照不能直接重试，需用最新配置新建运行。

## 验收

- 全部监督机忙碌时，中央仍能完成采集；多页完整查询后才发布候选，失败不发布部分结果。
- 工单池显示标题和开发人（单人、多人或未获取）；负责人仍参与筛选和启动通知，通知读取冻结快照，不额外查询 Jira。
- 预约后工单资格变化或执行机本地身份不符时本轮失败，不处理替代工单。
- 同组重名、跨组引用、版本冲突、Token 身份变更和引用中的账号删除均被拒绝；停用阻止新的采集和派发，已创建运行保持冻结身份。
- 校验真实 MySQL 8 的 V48 迁移、Windows CLI 身份核验、远程 Sidecar 和钉钉展示。H2 与模拟 HTTP 测试不能代替这些现场验收。

数据库升级为增量变更。不要用回退代码继续派发新账号格式快照；回退前停止调度并等待运行结束，保留数据库与历史记录。升级操作不授权修改任何实际 Jira 工单。

独立采集更新：8080 与 8091 必须配套升级并重启。启用的 Jira 任务每 30 秒自动采集，不再依赖 SOP 定时规则；定时规则和手动启动只负责派发。新增 SQLite 候选等待时间列和查询索引由网关增量初始化，不新增 MySQL 迁移。刷新浏览器后，分发中心显示自动采集说明及独立的 SOP 定时运行规则。参见 [独立周期采集说明](../services/python-workflow/README.md#jira-独立周期采集与派发)。

## 执行机与历史迁移检查

执行机须安装 PowerShell 7，入口使用 `C:\Program Files\PowerShell\7\pwsh.exe`，不回退到 Windows PowerShell 5.1。更新运行组件后重启实际使用的本机 MCP 或远程 Sidecar，无需重新安装 Jira CLI。中央 Token 不下发执行机，验收应核对执行机本地账号与冻结身份是否一致。

V47 时间列显式使用 `DEFAULT CURRENT_TIMESTAMP(6)`，业务代码负责写入时间。若旧部署曾在 V47 报 `Invalid default value for updated_at`，先只读核对 Flyway 失败记录、实际表结构及业务数据；仅修正脚本不能消除失败记录。修复须另行授权，不修改已应用迁移、不清理业务表或其他版本记录。
