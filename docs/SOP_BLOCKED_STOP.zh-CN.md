# SOP 阻断结束升级与验收

1. 等待旧活动运行结束，备份中央运行库和配置中心数据库；不要在执行中混跑新旧编排版本。
2. 协调更新中央网关、本机编排进程或远程 Sidecar，再更新配置中心及监控中心。配置中心启动执行新增 V36 迁移，不修改旧迁移。
3. 参考仓库 sop 下三份角色规则更新线上角色提示词，保留原业务非阻断条款。文件不会自动导入，历史运行快照不会改写。新运行默认使用新协议，已有运行不回填。
4. 使用专用测试 Jira 验证：第二步缺少必要条件时添加阻断评论，第三步不启动，显示停止原因，任务占用在收尾完成后释放。测试无评论权限、提交响应不明、重复回写、旧继续按钮及服务重启。
5. 验证首步无任务正常提前结束、不写无目标评论；正常成功流程仍可自动或半自动继续，主文档与等待讨论正常。
6. 在钉钉与网页检查“因阻断结束”“无待处理任务，已结束”、未执行步骤，以及 Jira 备注失败/未确认提示。核对在线与网关离线后的运行列表。

评论由业务模型使用既有授权工具提交。去重标记稳定，提交结果不明先核查，但不宣称外部评论严格一次写入。没有唯一 Jira 或缺少工具时不猜测、不安装、不提权，保存未备注原因并结束。

终态事件保留原事件类型并携带 termination；可通过状态接口和内部 supervisor.termination_pending 诊断收尾等待。停止决定保存后不再派发步骤，正常收尾确认前保留租约；远程失联仍遵守既有租约故障处理。真实 MySQL、执行机、Jira 和钉钉投递需在部署环境验收，本地测试替身不等于真实验收。
