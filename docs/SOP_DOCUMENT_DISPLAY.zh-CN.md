# SOP 文档展示与桌面宽版卡片

> 本文的单按钮、末步无等待卡片说明适用于旧运行；新版半自动的按钮与最后确认以[半自动三类等待升级说明](SOP_SEMI_AUTOMATIC_WAIT.zh-CN.md)为准，新策略不得回退旧单按钮模板。

## 全自动结束文档汇总

配置中心新建全自动运行冻结 `resultProtocolVersion=3`：正式步骤返回 `documents: [{name, path}]`，替代旧版单个 `document`，无交付文件返回空数组。其余业务结果字段沿用版本 2。每个业务步骤完成时立即采集明确交付的 UTF-8 `.md`、`.txt` 文件，单份最大 512 KiB；不扫描目录、不采集参考资料和敏感配置。逐份读取沿用每份十秒超时，失败条目保留名称及未同步状态，不改变合法业务结论。业务遇阻时也采集已交付清单；被中断且没有有效结果的步骤不补采。

中央保存每步正文快照，按依赖顺序汇总。同一执行机登记标识、同一规范化绝对路径的文档仅展示最后交付记录；不同路径或不同执行机的同名文件分别展示。Windows 路径不区分大小写。改名或移动按新文档处理，不推断关联。后续删除文件不影响已存正文；最新采集失败时保留上次成功正文并明确标记，不能将旧正文称为最新版本。原步骤链接仍可读取该步骤快照。

`GET /workflows/{workflowId}` 的顶层 `documents` 是最终版本汇总元数据，包含所属步骤的 `stepName/stepNumber`；各步骤 `documents` 为该步骤交付条目。来源指纹仅在受认证的内部上报及中央存储使用，公开接口不返回来源路径或指纹。远程仍通过带机器认证和租约的内部状态 API 提交快照，不读取 SQLite。

正常完成、无任务、遇阻、失败及人工取消时，有文档条目便用一张结束卡片替代原结束正文通知，展示真实结束状态、结束结果和全部文档入口；无文档时保留原通知。全部采集失败也列出失败条目，无成功正文的条目没有查看链接。没有五份上限、不分页、不折叠截断。通知仅发往既有目标或启动会话，保留原群聊提醒规则；仅聊天绑定不主动通知，不扩大阻断通知接收范围。

结束卡片复用下述宽版文档模板，`showConfirm=false/showStop=false`，不创建等待或控制操作。模板、正文、链接与接收目标随 Outbox 入队冻结；文档卡片入队和终态游标在同一事务内提交，以运行编号去重。明确未发送的临时错误沿用队列退避重试；永久错误或发送结果不明记录为 `abandoned` 并停止自动重发，后者错误说明为“结果未确认”。重启发现发送中的结束卡片也按结果未确认处理；不静默降级成另一份正文通知。卡片容量或真实投递失败须检查队列错误，不能通过截断文档入口掩盖失败。

版本 1、2 和没有版本字段的历史数据库运行保持原规则，不补采、不补发；按原快照重试不自动升级。网关未显式传版本的既有调用仍默认版本 2，配置中心新全自动运行显式提交版本 3。新建半自动运行使用下述版本 4，历史半自动版本 2 保持单主文档规则。

全自动步骤是否生成独立总结文件由 SOP／角色职责明确规定，平台不为每个步骤统一生成文件。职责要求的总结属于正式交付，不属于填充文档清单；阻断后仍允许在原工作目录和写入权限内完成该总结的写入、回读和交付，但不得据此修改业务代码、提交版本、移动业务方案或继续业务流转。无法安全写入或回读时，保留完整文字总结并说明文件未生成或未确认，不虚报交付、不重发结果不明的写入。此收尾例外不改变半自动遇阻等待规则。

## 新版半自动多文档

配置中心新建半自动运行冻结 `resultProtocolVersion=4`。仅第一业务步骤且存在下一步时采集多份文档；后续步骤和单步骤运行返回空 `documents`，不扩大采集范围。版本 1/2 和无版本的历史运行不升级，原快照重试也不升级。

正式结果使用 `documents: [{name, path, primary}]`。规划步骤的正式方案必须标为 `primary: true`，交接总结等附属文档为 `false`；最多一份主文档，按用途指定，不按文件生成顺序猜测。无正式方案时不把总结冒充方案。仅采集明确交付的 UTF-8 `.md/.markdown/.txt`，每份最大 512 KiB；不收录日志、参考资料、历史备份或敏感配置。复用受控文件读取，不扫描目录。

监控页和钉钉等待卡片展示全部条目，主文档排首位并标注“主文档”。失败条目保留名称、显示未同步；无已保存正文时不提供链接，不用总结替代方案。文档元数据新增布尔 `primary`，不公开源路径。主文档沿用稳定链接，改名或移动仍更新同一入口；附属文档按执行机及规范化路径保持身份。

等待回复“修改方案”时，只授权修改正式方案，不改写交接总结文件、其他附件或业务日志；其他文档只有用户明确指定才修改，对象不明确先澄清。供下一步使用的文字 `summary` 同步反映方案变更，不等于改写总结文件。讨论仅返回本次修改的文档清单；普通问答返回空数组和 `summary: null`。未列出的文档保持正文、版本和链接，主文档同步失败保留最近成功正文并明确提示。此规则通过执行提示词约束文件修改范围，并通过增量入库隔离文档快照更新；不新增执行机文件系统沙箱。

部署需同步更新中央 Python、实际执行的 MCP/Sidecar、配置中心及监控静态资源。无需新数据库迁移或更换钉钉卡片模板，仍需验证真实客户端展示。已有运行不自动补采、补发或更换文档；纠正历史入口须核验文件后单独明确修订，不直接修改数据库。

## 历史半自动行为

仅半自动 SOP 的第一个业务步骤且存在下一步骤时展示一份主文档；主监督不计入步骤。无步骤开关，不根据名称判断，运行时由中央服务按模式及步骤身份确定资格。半自动后续步骤和半自动单步骤 SOP 不采集；旧版全自动运行也不采集。新版全自动行为见上一节。

第一步以结构化结果返回 `summary` 和 `document`：后者为 `{name, path}` 或 `null`。平台只读取明确交付的工作目录内 UTF-8 `.md`、`.markdown`、`.txt` 主文档，保存独立正文快照，单份最大 512 KiB。拒绝越界、目录链接、特殊文件、隐藏路径、敏感配置目录和凭据文件，不扫描目录、不静默截断。

文档不改变总结和共享目录交接，不自动追加全文到下一步提示词。没有生成文件、读取失败、编码不符或超限均提示未同步，但不阻止已完成步骤继续；已有正文则保留最近成功版本。无效交接总结仍属于步骤结果错误。

等待讨论中普通提问不采集文档。明确修改后返回主文档描述，替换正文；`null` 表示没有可同步文件，保留旧正文并提示，不表示删除。文件改名、更换路径和第一步重试均沿用同一运行内的文档链接；新运行生成新链接。后续步骤不更新该文档。继续执行后，旧链接仍可读取保存正文。首版不提供文档增删管理。

兼容保留此前已保存的正文和旧链接，不主动清理数据库；如第一步原有多份文档，仅首份沿用为主文档，其他历史链接仍可读取。旧移除记录仍显示已移除。

## 读取和页面

- 网关：`GET /workflows/{workflowId}/documents/{documentId}` 返回最新版正文及状态；不提供文档列表 HTTP 接口。
- 监控中心提供同路径加 `/api` 的只读代理；浏览器不直连网关。
- 独立页面：`document.html?workflowId=...&documentId=...`，显示文档名、所属步骤、更新时间、版本及同步状态，每 10 秒刷新（隐藏页面不轮询）。
- 元数据包含 `id/nodeId/name/format/revision/updatedAt/error/removed/available`；正文响应另含 `content/stepName/stepNumber`，不返回来源路径或执行机地址。
- Markdown 使用本地固定版本 Marked 17.0.1、DOMPurify 3.3.3，禁用原始 HTML、图片和危险链接；纯文本保持换行。无 Node 构建步骤，许可证随 `static/vendor/` 保存。

文档页沿用可信内网访问边界。`WORKFLOW_MONITOR_URL` 必须是接收人桌面能够访问的监控中心地址，不能使用仅服务机器可访问的回环地址。无需公网开放服务。

## 宽版模板配置

已基于用户提供的 `config/sop等待选择卡片_1788953254627.json` 生成导入文件：[桌面宽版单文档模板](../config/sop等待卡片_桌面宽版_单文档.json)。保留原导出的外层封装和原“继续执行”按钮完整回调，移除该导出内已退役的返工、停止按钮及变量，拆分状态、步骤、总结、主文档入口和提示区域。

新文件沿用原 `Card` 根组件，设置已有字段 `autoWidth=true`、`fixWidth=false`、`fixedWidth=0`，关闭正文自动折叠，使用单列纵向布局。此配置基于导出中存在的字段；尚未在钉钉编辑器导入或真实桌面客户端验证，不能把本地 JSON 校验当作宽度已经生效。导入后请核对根容器的宽度选项和桌面预览；如果仍窄，使用编辑器实际提供的宽版/自适应选项调整并重新导出核对，不猜测额外枚举。

导入为新模板，先预览再发布。示例数据中的文档链接使用 `example.com`，仅用于排版，不是真实运行链接。可在预览中将 `hasDocuments` 改为 `false` 检查隐藏文档区域，将 `confirmStatus` 改为 `disabled` 检查按钮禁用；不要修改按钮回调及成功条件。新模板需要配套当前后端新增变量，不能直接替换未升级服务使用的旧模板。

从上到下配置：

| 区域 | 变量 / 组件 | 规则 |
| --- | --- | --- |
| 标题 | `title` 文本 | 任务标题 |
| 状态及步骤 | `statusText` Markdown、`steps` Markdown | 显示等待状态、已完成与下一步骤 |
| 本步总结 / 正式回答 | `summary` Markdown | 独立正文，全宽显示 |
| 交付文档 | `documents` Markdown | `hasDocuments=true` 时显示，包含主文档名称及一个查看链接 |
| 等待提示 | `notice` Markdown | 保持、处理中、倒计时、已结束等业务说明 |
| 操作 | 原“继续执行”按钮 | `showConfirm=true` 才显示，状态绑定 `confirmStatus` |

继续按钮必须保留当前模板事件链，回传 `action=advance_confirm`、`workflowId`、`gateId`，成功条件仍使用本次回调 `confirmRequestSucceeded`；不能仅凭请求发送成功显示业务成功。普通卡片不增加暂停、返工、跳过或聊天继续入口。半自动末步仍按等待策略处理；新版全自动结束卡片按上述规则隐藏全部操作按钮。

用户已提供新模板 ID `35c2fa5f-c25c-4d4b-8abd-dd07c953b14d.schema`，现设为新等待卡片的默认模板。部署新版并重启配置中心后生效；`DINGTALK_DOCUMENT_CARD_TEMPLATE_ID` 可覆盖默认值。显式设为空字符串时回退原单按钮模板，在正文追加主文档入口。模板 ID 在入队时写入持久化载荷，已入队及已发送卡片仍沿用其原模板协议，修改默认值或环境变量不重写历史卡片。模板 ID 已接入不代表已完成真实投递和桌面宽度验收。

## 部署与验收

1. 结束活动运行并按原部署流程备份；不要清库或修改已应用迁移。
2. 更新中央网关，再更新本机 MCP / 远程 Sidecar。中央 SQLite 自动兼容新增文档表，历史步骤开关列保留但不再参与判断；远程仍只调用带机器认证与租约的中央 API。
3. 更新两个 Java 服务。保留 Flyway V34（兼容旧步骤开关列，业务不再使用）和 V35（卡片文档刷新版本），不修改可能已应用的迁移。如果工作区曾构建其他分支，先用 `mvnd clean test`（macOS）或 `mvn clean test`（Windows）清理旧 `target`，避免残留同号迁移资源。
4. 配置可访问的监控中心地址，新建至少两个步骤的半自动运行，验证第一步主文档、缺失文档、非法路径、收录失败、改名及讨论同步；半自动单步骤和后续步骤不采集；另新建全自动单步骤与多步骤运行，核验超过五份、最后版本、无文档、部分失败和提前结束汇总。
5. 完成新模板配置、桌面预览及发布，核对默认模板 ID 或环境变量覆盖值。真实群聊 / 单聊投递、引用回复、按钮禁用恢复、旧卡失效、发送不明确后的重试，需要指定目标后验收。

真实执行机必须支持 `fs/getMetadata` 和 `fs/readFile`；不支持时显示未同步，不执行替代脚本。代码测试不代替真实 MySQL 迁移、远程文件接口与钉钉平台验收。

全自动汇总升级需同步更新中央网关、本机 MCP／远程 Sidecar、配置中心和监控中心；复用现有 SQLite 文档表与 MySQL Outbox，无新增数据库迁移。先结束活动运行并备份，再升级，使用新运行验收；只升级配置中心会让旧网关拒绝版本 3。模板环境变量若覆盖为空或指向旧模板，须先改为已发布的宽版模板；结束卡片不会回退等待模板。检查接收人的监控链接可达性、群聊和单聊实际投递、桌面/移动端全部文档及隐藏按钮。单元测试不能替代真实平台验收。
