# 分组机器管理部署

## 一次准备，网页登记

此模式用于可信内网。远程执行服务与主监督 Sidecar 由维护人员提前部署，网页不安装软件、不生成令牌、不修改远程权限。运行期间不要修改组和机器配置；系统不做运行中配置锁定。

中央网关、配置中心 8091、本机兼容 MCP 和远程 Sidecar 都设置 `CODEX_AGENT_SOURCE=registry`。缺省为 `file`，保持原文件模式；两种来源不合并。8090 不需要改变。

中央 SQLite 新增机器分组、机器登记、一次性导入记录三张表，启动时兼容创建，不修改已有工作流数据。备份中央运行库即包含机器登记；远程仍不读写 SQLite。

中央网关配置下列统一默认值，新增机器时保存为该机器配置。后续更改这些默认值不追溯覆盖已登记机器：

| 环境变量 | 约定 |
| --- | --- |
| `CODEX_MACHINE_CWD` | 必填，执行机上的统一绝对工作目录，远程需预先创建 |
| `CODEX_MACHINE_PROTOCOL` | `ws`（默认）或 `wss`；网页端口指执行服务端口，默认填写 4500 |
| `CODEX_MACHINE_MODEL` | 默认 `gpt-5.6-sol` |
| `CODEX_MACHINE_TOKEN_ENV` / `CODEX_MACHINE_TOKEN_FILE` | 执行服务凭据引用，最多选一项；必须在中央和所有实际派发的远程主监督上能解析为对应执行服务接受的凭据 |
| `CODEX_MACHINE_SIDECAR_TOKEN_TEMPLATE` | 新增主监督必填，中央本地的绝对路径模板，如 `C:\codex-secrets\sidecars\{ip}-{port}.token`；IPv6 的冒号替换为下划线 |
| `CODEX_MACHINE_ALLOW_WRITE` | 默认 `false`；统一允许工作区写入时明确设置 `true`；不启用完全访问，也不允许请求覆盖目录 |

统一的是路径和部署方式。每台主监督的 Sidecar 机器令牌仍必须独立，中央对应文件与该远程机 `CODEX_GATEWAY_TOKEN_FILE` 或 `CODEX_GATEWAY_TOKEN_ENV` 解析出的值必须匹配。不能多台主监督共用机器令牌，不能与执行服务凭据混用。实际令牌不写入 JSON、数据库配置字段、页面或接口响应。

远程主监督设置中央 `CODEX_GATEWAY_INTERNAL_URL`、自身机器令牌来源以及 `CODEX_AGENT_SOURCE=registry` 后启动 Sidecar。登记模式可省略 `--agent-id`：真实身份由中央根据唯一机器令牌确定，启动标签不参与鉴权，不需要登记后再次复制生成的编号。未登记前心跳失败会重试；网页登记后自动识别。不再需要本地执行机清单。Windows `scripts/start_workflow_sidecar.ps1` 支持相同规则。

Sidecar 仍只监听 `127.0.0.1:8082`，主监督执行服务的编排工具地址仍为本机 `/mcp`。不要将此端口对外开放。中央以及组内每台主监督必须能通过登记的 IP、端口访问组内执行服务；第一版不维护每个访问来源的不同地址。纯执行机只需已启动执行服务，不要求安装 Sidecar。

## 操作

1. 在 8091 “机器管理”中新建分组。
2. 添加机器，填写 IP、执行服务端口、分组及能力；可以同时选主监督和执行机。页面不接受域名。编号自动生成，名称默认用 IP。
3. 点击“检测连接”。纯执行机验证执行服务协议连接及认证；远程主监督还要求有效 Sidecar 心跳。此操作不创建任务，不验证模型登录额度、业务工作区实际访问或真实业务产出。
4. 检测通过且启用后可提交运行；修改 IP、端口、能力或分组会清除检测结果。在线状态与检测记录分别展示，历史检测通过不保证后续网络始终在线。
5. SOP 选择主监督后，只建议同组执行机。登记模式保存时要求机器已登记且能力、分组匹配；提交时额外要求启用并检测通过。网关不可用时无法完成登记模式的 SOP 校验。文件模式仍允许脱机保存。

机器可以编辑和启停，没有物理删除。非空组不能删除；可以编辑机器归属后删除空组。同组不是网络防火墙隔离，只限制平台派发。不同组不能混用于一个 SOP，组内允许多个主监督，主监督固定容量仍为 1。

远程 Sidecar 按需通过认证的 `/internal/v1/agents` 获取本组连接配置，包含执行服务凭据引用，不含实际令牌和 Sidecar 认证引用。不会把清单写回本地文件。中央步骤派发再次检查同组、能力、启用和检测结果，不能以伪造执行机编号越组。

## 旧部署迁移

在无活动任务的维护窗口备份中央 SQLite，升级中央及本机 MCP/远程 Sidecar，并为这些进程和 8091 设置登记模式。保持网关 `--agents` 指向原配置，但此时它只用于显式导入，不作为运行清单。

进入机器管理点击“导入旧配置（一次）”。系统读取网关指定的旧文件，保留原编号、地址、目录、权限与凭据引用，放入默认分组，不删除文件。全批次成功才记录已导入；编号或地址冲突时整批失败，不覆盖已登记记录。旧域名地址允许导入保留并启停；网页新建或变更地址只接受 IP。

导入机器均为未检测，需要逐台检测。旧 SOP 和历史快照的机器编号不改写；按历史快照运行仍使用原编号并执行新的可用性与同组校验。迁移后不要继续修改旧文件期待网页登记同步变化。

回退到文件模式需在维护窗口统一切换中央、本机 MCP、远程 Sidecar 和 8091；网页新增机器不会自动写入旧文件，回退前需按部署流程准备对应文件。运行库保留，不清表。

## 接口

8091 管理接口由 Java 代理到中央对应去除 `/api` 前缀的路径：

```text
GET/POST   /api/agent-groups
PUT/DELETE /api/agent-groups/{id}
GET/POST   /api/agents
PUT        /api/agents/{id}
POST       /api/agents/{id}/test
POST       /api/agents/import
```

新建/编辑机器请求包含 `ip`、`port`、`groupId`、`capabilities`、`enabled`；能力为 `supervisor` 和/或 `executor`。机器列表保留旧字段，登记模式增加分组、IP、端口、检测状态和时间；顶层 `source` 标识来源。分组请求为 `{"name":"分组名称"}`。

中央 `/agents/validate` 供 Java 保存 SOP 时校验，请求为 `supervisorId` 和 `executorIds`；它不校验检测资格。新增内部 `GET /internal/v1/agents` 沿用机器认证，仅返回认证主监督所属组。

检测业务失败返回 `passed:false` 与普通中文提示，错误类型记入服务日志，不回显底层异常。组/机器输入无效返回 400；文件模式调用管理接口返回 409。管理接口只用于原有受保护内网。
