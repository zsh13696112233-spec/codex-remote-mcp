# 钉钉单机器人多任务绑定实现说明

## 1. 目标与边界

当前版本仍只配置一套钉钉企业内部应用凭证和一条 Stream 长连接，但机器人不再固定一个任务定义。任务定义可以选择一个钉钉人员或群聊作为通知与控制入口：

- 一个任务定义最多绑定一个对象。
- 一个对象只能绑定一个未删除的任务定义。
- 多个任务定义可以引用同一个 SOP，并分别绑定不同对象。
- 同一绑定同时最多运行一个工作流，不同绑定可以同时运行。
- V17 起，钉钉发起的运行始终建立工作流绑定；任务定义开启主动通知后，8091 页面和定时运行也建立绑定并回推消息。
- 飞书的固定任务和全局单任务规则不变。

## 2. 数据模型与迁移

Flyway `V14__move_dingtalk_targets_to_tasks.sql` 在 `codex_sop_task_definitions` 增加：

| 字段 | 含义 |
| --- | --- |
| `dingtalk_target_id` | 任务绑定的人员或群聊，允许为空并带唯一约束 |
| `dingtalk_active_workflow_id` | 当前占用此绑定的工作流 ID |

唯一约束保证同一通知对象不能被两个任务定义绑定。`dingtalk_active_workflow_id` 是持久化的任务级执行槽：锁定一个任务定义不会阻塞其他任务定义。

迁移会把 V1 机器人设置中的固定任务及其 SOP 通知对象复制到该任务定义，并把旧的全局活动工作流复制到任务级执行槽。随后清空 SOP 的旧目标和机器人设置中的固定任务字段；旧列、旧全局状态表保留用于结构兼容，但运行代码不再读取。

## 3. 配置与 API

任务定义的创建、更新和查询增加：

```json
{
  "dingtalkTargetId": "通知对象 UUID 或 null",
  "dingtalkTarget": {
    "id": "通知对象 UUID",
    "targetType": "GROUP",
    "displayName": "运维群",
    "available": true,
    "enabled": true
  },
  "dingtalkActiveWorkflowId": null
}
```

`POST/PUT /api/task-definitions` 使用 `dingtalkTargetId` 保存或解除绑定。换绑、解绑或删除任务时如果任务仍有活动工作流，接口返回冲突；停用任务不会切断既有工作流的对话控制，但会阻止新运行。

钉钉配置接口不再接收或返回 `taskDefinitionId`。机器人可以在零任务绑定时启用，以便在新群首次 @ 时自动发现群。机器人页面展示已有任务绑定，绑定操作统一放在任务定义编辑页面。

## 4. 消息路由和并发原理

收到消息后，系统先将来源归一化：群聊使用 `GROUP + openConversationId`，单聊使用 `PERSON + senderUserId`。`DingTalkTaskBindingDirectory` 使用通知对象反查任务定义，并对该任务行执行 `FOR UPDATE`：

1. 没有绑定时返回 `unauthorized`，不创建运行。
2. 任务、SOP 或通知对象不可用时返回稳定的业务冲突。
3. 该任务已有 `dingtalk_active_workflow_id` 时返回 `busy`。
4. 空闲时创建最新配置运行快照，把新工作流 ID 写入任务执行槽。
5. `DingTalkStore` 同事务创建工作流消息绑定，冻结任务 ID、目标类型、目标外部 ID 和显示名称。

两个群对应不同任务行，因此可以同时获得各自的执行槽。相同群的并发启动会在同一任务行串行化，最终只有一个请求成功。

顶层提问按消息来源查找该目标当前活动工作流；回复、引用和卡片回调仍按已经冻结的工作流绑定查找。终态事件只释放该工作流所属任务的执行槽，不会清除其他群或人员的活动任务。服务重启后，任务级执行槽、工作流绑定、事件游标和 Outbox 都从 MySQL 恢复。

## 5. 关键代码

- `domain/DingTalkTaskBindingDirectory.java`：目标反查任务、任务行锁、占用、重启重新占用和终态释放。
- `domain/TaskDefinitionEntity.java`：保存任务目标绑定和任务级活动工作流。
- `integration/dingtalk/DingTalkStore.java`：启动幂等、工作流绑定、消息路由、事件游标和 Outbox 事务。
- `integration/dingtalk/DingTalkBotCoordinator.java`：按消息来源启动或找到活动任务，并将咨询和控制转发到正确工作流。
- `static/app.js`：任务编辑绑定、对象占用提示和机器人绑定列表。

## 6. 失败与变更语义

- 通知对象被停用或通讯录同步标记不可用后，不允许新启动；已经运行的任务仍依赖冻结目标正常收发和控制。
- 活动期间允许修改任务正文或 SOP；不可变运行快照保证当前运行不受影响，新配置在下一次运行生效。
- 活动期间禁止换绑、解绑和删除任务，避免执行槽与管理配置脱节。
- 修改机器人应用、密钥、启用状态或卡片模板时，只要当前应用仍有任一活动绑定就拒绝保存。
- 群 A 的顶层指令、回复和卡片动作只能解析到群 A 的工作流，不能控制群 B 或个人绑定的工作流。

## 7. 验证重点

- Flyway V1 至 V14 可在 H2 MySQL 兼容模式完整执行；正式发布前仍应在真实 MySQL 8 验证一次升级。
- 同一 SOP 的两个任务绑定两个群时可以同时启动，结束其中一个不会释放另一个。
- 同一目标重复绑定被领域校验和数据库唯一约束共同拒绝。
- 同一绑定并发启动只创建一个活动工作流；重复消息保持幂等。
- 群、人员、Markdown、互动卡片、任务助手、半自动控制和 Outbox 补发保持原有行为。
