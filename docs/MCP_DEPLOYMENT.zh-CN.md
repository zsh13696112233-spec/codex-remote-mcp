# MCP / CLI ZIP 下发与 Agent 安装

配置中心新增 MCP 管理。浏览器只访问 8091，Java 代理中央网关；包、分组关联、安装记录和占用保存在中央 SQLite。纯执行机不增加 Sidecar，8090 不增加安装入口，SOP 标签语义不变。

## 配置和使用

1. 中央配置增加 `mcp_deployment.package_root`，填写中央专用绝对目录；省略时关闭下发。参见 `config/workflow-service.example.json`，不要覆盖实际服务配置。
2. 先升级中央 Python 及共享存储代码，再更新 8091。暂停业务后升级，确保本机 MCP 与远程派发都使用新的中央互斥逻辑。
3. 在机器管理启用独立 MCP 安装授权，只填写一个 Windows 安装目录并预先创建。Python、Node.js 的位置由安装助手自行查找，无需填写运行时路径；环境缺失则报告失败，不自动安装。机器仍需已有写权限、执行能力和连接检测资格。
4. 附带 Skill 使用同一机器的 Skill 安装授权和目录。没有授权却含 Skill 的安装不能验收成功。
5. 选择分组、上传 ZIP、选择执行机下发。在执行机页签查看状态；待配置表示已注册但连接或工具发现尚未通过，准备地址和账号后再检测。安装过程不配置账号、不执行 Jira 或 GM 业务操作。

不要求用户提供哈希或安装清单。ZIP 最大 20 MiB，解压总量 200 MiB，单文件 32 MiB，最多 1000 文件；拒绝路径穿越、链接、加密、重复路径和大小写冲突。内部摘要仅用于包身份和一致性校验。中央将原包和安全解包的文件经已有认证文件接口传到独立临时目录，Agent 阅读这些文件并决定安装入口，不自行联网下载依赖。安装轮次启动前的连接失败最多重连两次，文件回读或分块合并校验一致才继续；安装脚本不自动重放。

## 大文件分块传输

- 原 ZIP 和解压出的每个文件分别判断大小：不超过 8 MiB 沿用原文件接口；超过 8 MiB 按 4 MiB 分块上传，每块回读比对。这样每次 Base64 请求保持在约 5.34 MiB，而不是发送完整大文件。
- 大文件要求当前机器登记同时允许 `allow_write` 和 `allow_full_access`，未授权时在创建安装目录和上传前返回中文提示，不自动提权。授权来源仍为中央 `machine_defaults`，修改后需重启网关并在机器管理保存同步；任务仍核对冻结快照，授权或连接发生变化的旧任务不会绕过检查。已满足授权且仅因超限失败的任务，升级网关后可直接使用原任务重试。
- 传输阶段只有平台固定合并代码通过 `command/exec` 使用 `dangerFullAccess`。代码通过编码命令发送，不执行包内或缓存中的脚本；参数用 Base64 JSON 编码，包路径不会插入命令源码。默认使用执行机 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`，不存在或被禁止时停止，不修改 PATH、执行策略或执行服务配置。非标准 Windows 系统目录暂不自动发现。
- 临时包目录内的 `.mcp-transfer` 为平台保留缓存名，ZIP 不得包含该路径段。缓存标记绑定安装任务及文件路径、大小和哈希；已有目录归属不明、文件或分块被改动时停止，拒绝覆盖。合并代码再次检查目录祖先及文件不是链接，校验每块和完整文件的 SHA-256 后，在同卷内发布最终文件，拒绝覆盖已有目标。
- 响应丢失后，重连或原任务重试会回读核对已有分块；最终文件已发布时只在执行机重新计算大小和哈希，不重新上传或整文件回传。每个文件使用独占合并锁，旧命令仍运行时新命令停止，待旧命令结束后可再次重试。持久依据是原安装记录、目录标记和实际文件，不依赖网关进程内存。
- 分块缓存保留在该任务临时目录中供恢复使用，会额外占用大文件总大小的磁盘空间。正常失败仅清理本次创建的随机合并临时文件；进程强制退出留下的未知临时文件不自动删除，也不会作为安装文件使用。外部管理员并发修改目录仍存在检查与使用间的竞态，应使用专用受信目录；完全访问命令不具有操作系统沙箱隔离。

本修复只需升级并重启中央 Python 网关，无接口或数据库迁移，两个 Java 服务及执行机默认配置无需因代码修复而改变。重启应避开运行中的工作流。若需要修改机器权限，必须先按上述步骤处理授权；不同授权快照或归属冲突的已有目录需人工核对，不通过删库或清空安装目录解决。

## 权限与验收

安装助手返回显式 `kind: mcp | cli`，平台据此分流验收：

- **MCP + Skill**：复制程序和附带 Skill，注册真实 STDIO 入口，并验证工具发现和 Skill 识别。兼容没有 Skill 的独立 MCP 包。
- **CLI + Skill**：复制程序和配套 Skill，不写 MCP 配置、不要求 MCP 工具发现。平台验证安装后的入口 `--help` 返回零退出码及非空输出，并使用强制刷新 Skill 列表检查其入口、启用状态、名称唯一性及解析错误。CLI 没有配套 Skill 时不支持安装。

程序及运行所需资源必须放入程序目录，Skill 及其引用资源放入 Skill 目录；安装提示要求 Skill 命令示例使用正式程序绝对路径，不依赖 PATH 或临时目录。平台检查入口文件存在、目录边界和链接，并独立验收；模型报告 installed 不等于最终成功。

CLI 验证只支持原生 `.exe`（无额外参数），或已有 Python/Node 加单个安装目录内脚本路径，再由平台追加固定 `--help`。Windows 执行服务的 `command/exec` 沙箱限制下，此检查要求冻结的机器登记同时允许 `allow_write` 和 `allow_full_access`，使用完全访问执行；没有授权则停止，不自动提权。不执行登录、菜单或其他业务命令，不保存或展示帮助输出；帮助行为由程序自身实现，不具备操作系统沙箱隔离。安装助手仍使用限定目录沙箱。

### 终端命令与 PATH

- 需要终端调用的 CLI 必须加入 **执行服务运行账号的用户 PATH**；兼具 CLI 的 MCP 同样处理。纯 MCP 服务、独立 Skill 及配套 Skill 目录不加入 PATH。不修改所有账号共享的机器级 PATH；使用其他账号打开的终端不会自动获得这个入口。
- 安装结果新增 `terminal: {command, args} | null`。CLI 的终端入口与原入口相同；混合 MCP 单独报告无 MCP 启动参数的 CLI 入口，主入口仍按原绝对路径注册；纯 MCP 返回 null。平台校验入口为安装目录内 EXE，或已有 Python/Node 加一个安装目录内脚本，并执行固定 `--help`。
- EXE 将其所在目录加入 PATH，以文件名（去掉 `.exe`）作为命令名。脚本由平台在脚本旁生成同名 `.cmd`，以绝对路径调用已有运行时并转发参数，再加入启动器所在目录；不把 Python/Node 安装目录加入 PATH。命令名只接受英文、数字、下划线、连字符；路径拒绝 PATH 分隔符和命令展开字符。脚本启动器当前只支持 ASCII 路径，遇到中文等路径明确失败，不生成乱码启动器；EXE 不受此 ASCII 限制。
- PATH 步骤使用固定 PowerShell 代码及编码参数，要求冻结机器已授权写入及完全访问，不扩大安装助手权限。固定代码复核平台目录标记、文件和祖先非链接；不覆盖内容不同的启动器。按账号互斥，保留原用户 PATH 和注册表值类型，去重后追加；不把执行服务进程的旧 PATH 写回注册表。
- 使用持久化机器 PATH 与拟更新的用户 PATH 构造独立验收进程环境，检查命令名是否解析到本次入口；同名命令遮蔽、文件异常或写入回读失败均不能报告完成。已有终端、IDE 或执行服务仍可能保留旧环境，需要重新启动以取得新 PATH；平台发送环境更新通知但不自动重启服务。MCP 注册和 Skill 示例仍保留绝对路径，避免依赖旧进程的 PATH。
- 响应丢失后可重新检测，已加入目录不重复追加；已写入的 PATH 和生成的启动器不会因后续 Skill/MCP 验收失败自动回滚。只在全部对应验收通过后报告安装完成。外部管理员并发编辑注册表仍存在检查与写入间竞态，避免同时手工修改 PATH。
- 升级中央 Python 网关后，已有 `kind=cli` 记录点击“重新检测”可从原入口补做 PATH，仍须满足原授权和目录归属。旧 MCP 记录没有终端入口证据，不能据主入口猜测它兼具 CLI，重新检测不会自动加入 PATH；仅新安装分析返回的 `terminal` 触发混合 MCP 的 PATH 步骤。不自动重放旧安装脚本，不需要数据库迁移或 Java 接口变更。

针对性测试增加 `tests.test_mcp_terminal`，与 `tests.test_cli_installation`、`tests.test_mcp_installation`、`tests.test_mcp_deployment` 一起运行。Windows 固定脚本测试替换注册表存储与环境广播，仅在临时目录验证去重、命令冲突、目录归属及恢复，不修改测试机器的真实 PATH；不代表远程生产账号注册表权限已验收。

### 安装恢复与边界

逐机结果新增 `installation.kind`；旧 installed 结果缺少此字段时按 MCP 恢复，无结果时为 null，不需要数据库迁移。CLI 的 `diagnostics.kind=cli`，不提供 MCP 连接状态或工具数量。页面分别显示类型和程序、Skill 验证状态。

旧 unsupported 任务点击“重试”会清除旧结果及安装会话，重新分析安装包；已取得 installed 结果则仅按持久化类型重新验收，不自动重装。授权或连接快照变化时需重新下发。若先前目录已由用户清理，可以从包库重新下发；无需重新上传同一 ZIP。部署本功能需升级中央 Python 网关及配置中心静态资源，然后刷新页面；避开运行中的任务重启服务。

安装使用独立会话和机器默认模型，整个任务最多 30 分钟。程序位于 `安装目录/mcp-包摘要前16位`，临时文件位于 `安装目录/.mcp-tmp-任务编号`，二者分开，Skill 使用独立包子目录。平台持久化任务归属并写入目录标记；已有未知目录不认领、不覆盖。未提供 HTTP MCP 或普通 CLI 自动包装功能。

安装助手显式请求 `workspace-write`、`approvalPolicy=never`、限定写入根目录、关闭网络和隐式临时写入目录；不修改 PATH、不允许安装助手降级到完全访问。大文件传输中平台固定合并代码的独立权限见上一节。执行服务返回的安装策略必须与请求一致，否则不启动安装轮次。安装会话关闭已有 MCP、插件和应用配置，安装说明不得改变权限。沙箱限制写入范围，读取限制不等同于“只能读取安装目录”；提示词禁止读取凭据，执行机应使用专用服务账号和受信安装包。

Agent 只返回结构化安装结果。对 MCP 类型，平台检查程序、工作目录和脚本入口范围，注册单个 MCP 条目，保护 `codex_orchestrator` 和同名人工配置。用户层写入必须提供版本标记，响应丢失后对账，不覆盖整份配置。程序注册后使用新的只读验证会话，要求发现非空工具列表且无工具发现错误；执行服务提供连接状态时必须为 `connected`。兼容缺失或空的 `runtimeStatus`，此时按工具目录验收通过，但明确标注未提供连接状态，不能据此宣称实时连接或业务调用已验证；工具目录可能来自执行服务缓存。分页游标不能重复。附带 Skill 必须可识别且启用。

工具发现成功不等于业务账号、服务权限或所有工具已完成业务验收。平台不通过执行写操作测试安装。首版不提供更新、卸载、回滚及目录迁移。

安装记录及批次详情展示最近检测时间、检测阶段、是否找到服务、连接状态、工具数量和分类失败原因；旧任务无记录时提示重新检测。响应中的 `diagnostics` 由中央持久化，Java 原样代理。工具数量未知与零工具分开显示；连接成功且存在工具仍不代表已执行过业务调用。错误仅分类为缺少服务地址、认证失败、超时、访问拒绝、握手失败、连接关闭或无法分类，不存储和展示原始错误、凭据及内部地址。重启中断的检测取消“检测中”标记，保留历史时间并提示重新检测。

## 中断与互斥

安装前按权限含义核对执行服务返回的沙箱策略：Windows 路径大小写和根目录排列顺序不影响匹配，但不得增加写入目录、开放网络或隐式临时目录。失败信息区分只读模式、目录范围、网络及审批策略不一致；只读模式不能执行安装，须检查执行机沙箱支持与服务策略，不降级到完全访问。

`workspaceWrite` 返回的 `writableRoots` 可能省略隐含可写的工作目录。平台必须确认返回的 `cwd` 是本次临时目录，再将它和返回根目录取并集进行比较；缺少程序或 Skill 目录、增加其他目录仍拒绝。字段说明参见 [官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

每台机器串行，最多三台同时处理。中央事务保证 MCP 安装与 Skill 执行互斥；存在非终态工作流引用的机器等待空闲。MCP 占用期间拒绝新增工作流、返工及中央步骤派发，也禁止修改机器登记。占用保存在 SQLite，不依赖进程内锁。

安装轮次发出前先持久化启动意图。网关退出或连接失败后，已发起安装的任务保留占用并显示“待核对”，不盲目重放脚本；尚未发起安装轮次的准备任务显示失败并释放占用。重新检测读取远程安装会话，确认已停止后才能验收或释放占用。旧记录若无法确认启动阶段或会话编号，则需要维护人员核对，不能以“没有编号”认定远程未运行。此情况首版没有强制清除占用按钮。

已确认停止但安装失败的任务可重试，先核对目录归属和既有包文件；已取得有效安装结果的任务仅重新注册和验收。遇到变化停止，不删除文件。重试重新核对冻结的连接、分组和目录授权，撤销授权后不能沿用旧任务安装。排队安装期间也禁止修改机器设置。中央运行库旁 `.mcp.lock` 防止多个管理进程并发恢复。

## 接口

浏览器路径有 `/api` 前缀，网关路径没有：

| 路径 | 操作 |
| --- | --- |
| `/mcp-packages` | GET 按 groupId 查询，POST 原始 ZIP，上传必须给 groupId |
| `/mcp-packages/{id}` | GET 包详情 |
| `/mcp-packages/groups/assign` | POST `{groupId, packageIds}` |
| `/mcp-packages/machines` | GET 机器及授权 |
| `/mcp-packages/inventory` | GET 安装记录 |
| `/mcp-deployments` | GET 批次；POST `{requestId, groupId, packageId, agentIds}` |
| `/mcp-deployments/{id}` | GET 逐机结果 |
| `/mcp-deployment-tasks/{id}/retry` | POST `{requestId}`，失败任务重试 |
| `/mcp-deployment-tasks/{id}/check` | POST `{requestId}`，重新检测 |

请求编号为 UUID，相同编号不同内容冲突。页面不会展示原始模型输出、完整执行服务配置、会话编号或凭据。新增机器字段 `mcpInstallation` 包含 `enabled`、`platform: windows`、`installRoot`；省略保留原值。旧配置和历史任务仍兼容 `temporaryRoot`、`programRoot`、`runtimes`，不自动迁移文件；机器编辑页回填旧程序根目录，保存后新任务采用单目录布局。平台只接受安装目录内的程序或已有的 Python/Node 可执行文件（兼容旧运行时列表），验证路径和文件类型，且运行时首参数必须为本次安装目录内脚本。

## 测试和当前验收限制

安装断连时，中央网关日志记录安装任务编号、是否已启动/停止安装及 `close_code`；请求期间断连还记录 `method` 和 `request_bytes`（完整 JSON 请求的 UTF-8 字节数，不含 WebSocket 帧开销）。未列入诊断白名单的方法显示为 `other`，未取得关闭码时显示 `None`。日志不输出请求参数、文件内容、连接地址、凭据或原始关闭原因。等待安装结果时没有正在执行的请求，因此可能只有安装断连日志；关闭码本身不能单独证明根因。更新网关代码并重启后生效，历史失败无法补回这些信息。

需要验证大文件传输时，可使用仓库根目录的 `scripts/probe_mcp_file_transfer.py`。先确认目标安装目录已授权、执行机空闲，再显式指定地址、目录和从小到大的大小，例如 Windows 下运行 `.venv/Scripts/python.exe scripts/probe_mcp_file_transfer.py --url ws://192.0.2.20:4500 --root C:\mcp-test --sizes 8 11 12 --token-env MCP_PROBE_TOKEN`。凭据由本机环境变量提供，不通过命令参数传入实际值；仅在用户明确授权后可改用 `--gateway-credentials` 在内存中复用中央默认凭据引用，不读取运行数据库。macOS 使用 `.venv/bin/python`，远程 Windows 路径需按本机 shell 正确引用。

脚本生成独立随机临时目录，通过 `fs/writeFile` 写入随机测试数据并回读校验 SHA-256，首次失败立即停止；不启动模型、安装程序或业务工具。成功时仅非递归删除本次文件和空目录；断连时保留打印出的测试目录供核对，清理前确认目录归属和内容，不递归删除安装目录。请求字节数包含 Base64 及 JSON 开销；大小相关的稳定失败只能定位传输限制，不能单凭关闭码区分代理与执行服务。
